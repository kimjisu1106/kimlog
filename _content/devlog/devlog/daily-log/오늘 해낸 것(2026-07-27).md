## 어려웠던 점

- (소리꽃 KeyBloom) 하우스 광고를 앱이 직접 그릴지, 온실이 주는 SDK를 받을지 정해야 했다. SDK 방식은 앱 코드가 줄고 광고를 바꿔도 앱 재배포가 필요 없지만, 원격 코드를 앱 안에서 실행하는 신뢰 표면이 생긴다. 같은 소유자인 데다 애드핏 같은 광고 SDK의 표준 모델이라 감수하기로 하고, 대신 링크는 앱에서 https만 열게 한 번 더 걸렀다
- (소리꽃 KeyBloom) 실시간 연주로 바꾸면 미리보기 크기가 출렁였다. 하단을 통째로 숨겨 자리까지 사라진 게 원인이라, 시퀀서는 자리는 남기고 내용만 비우게 바꿔 두 모드의 미리보기 크기를 맞췄다
- (온실 GreenHouse) 배포하고 바로 확인하면 요청마다 새 버전과 예전 버전이 섞여 나왔다. 엣지 서버마다 새 배포가 도는 시점이 달라서(최종 일관성), 한 번 성공을 믿지 않고 연속 여러 번 새 버전이 나와야 완료로 판정하게 확인 방식을 바꿨다
- (온실 GreenHouse) 배너를 어떤 방식으로 만들지가 애매했다. 포토샵 없이 HTML 카드를 헤드리스 브라우저로 스크린샷 찍는 파이프라인으로 정리 — 색·문구 수정이 CSS 편집이라 앱별 색 변형 6장도 금방 나왔다
- (온실 GreenHouse) 셋 다 온실 그린이라 단조롭다는 걸 배너 세 장이 모이고서야 알았다. 앱별 정체성 색으로 갈고, 🌱 마크만 공통 브랜드로 남겼다
- (콘티온 Conti On) 자막 담당자가 iPad에서 콘티 순서를 못 바꾼다고 했다. 웹 드래그가 터치에선 이벤트 자체가 안 나는 근본 문제라, 드래그 라이브러리를 새로 얹는 대신 라디오로 고르고 공용 버튼으로 올리고 내리는 방식으로 정했다(데스크톱 드래그는 유지). 그룹 안팎은 위치로 갈리니 넣기/빼기 한 버튼으로 토글
- (콘티온 Conti On) 찬양 catch-all을 '기타'로 하려다, 예배 순서지에도 '기타'가 있어 이름이 겹치는 걸 확인했다. 카테고리 이름이 전역에서 유일해야 하고 그 이름으로 대분류를 역추적하는 구조라, 찬양은 '그 외'로 갈랐다
- (콘티온 Conti On) PPT를 뽑아야만 결과를 볼 수 있었다. 내보내기 전 미리보기를 넣되, 미리보기와 실제 PPT가 어긋나면 못 믿으니 슬라이드를 만드는 로직을 한 곳으로 모아 둘이 공유하게 했다
- (모래게임 Sandrop) 붓기 소리를 화면의 붓는 그림에 자연스럽게 붙이는 게 관건이었다. 레일 도착이 아니라 실제 붓는 순간에 나야 하고, 여러 바구니가 동시에 부어지면 소리도 겹쳐야 두껍고, 붓기가 끝나면 붓는 시간에 맞춰 사라져야(소리가 그림보다 오래 남으면 어색) 자연스럽다. "지금 붓는 바구니"를 소리 쪽이 계속 받아 바구니마다 켜고 끄는 방식으로 맞췄다
