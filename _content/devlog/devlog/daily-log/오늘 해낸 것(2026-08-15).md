## 오늘 한 일

- 메트로놈 Simple Metronome
	- Play 스토어 등록정보를 새로 씀 — 밋밋하던 설명을 기능(BPM·박자표·드럼·비트 플래시·백그라운드 재생 등)이 드러나게 한국어·영어로 다시 작성해 등록
- 룸톤 Roomtone
	- 확인 끝낸 곡을 다시 올릴 땐 보컬 검사를 건너뛰게 함 — 시작할 때 검사할지 묻고 진행
	- 보컬 검사 속도 개선 — 곡마다 새로 하던 걸 한 번에 모아 처리해 무거운 준비를 한 번만, 엔비디아 그래픽카드가 있으면 자동 가속
	- 어떤 분위기의 곡이 부족한지 사업군 기준으로 정리하고 보강 계획 문서로 남김(우아·세련 우선, 생성 프롬프트 포함)
	- 곡 에너지(잔잔↔활기)를 템포로 자동 분류 — 올릴 때 초기값을 매기고 기존 208곡도 일괄로 채움
- MiniMacro
	- 마우스·키보드 반복 작업 자동화 미니 툴을 새로 만듦 — 클릭·이동·키·텍스트·대기 단계를 목록으로 편집하고, 실제 조작을 녹화해 단계로 변환하고, 반복 횟수·작업 사이 대기를 정해 재생
	- hover로 열리는 메뉴 대응 — 클릭을 이동과 클릭 두 단계로 나누고, 커서는 좌표로 순간이동
	- 듀얼 모니터에서 재생 위치가 어긋나는 문제 해결
	- GitHub 저장소에 올리고 CLAUDE.md 작업 원칙 정비

## 어려웠던 점

- 메트로놈 Simple Metronome
	- 영어 간단한 설명이 80자 제한이라, 기능을 다 넣으면서 "background playback"까지 온전히 담으려고 문구를 여러 번 줄여 다듬었다
- 룸톤 Roomtone
	- 재즈·잔잔한 곡을 넣으니 보컬이 없는데도 보컬로 걸리는 게 많아, 고칠 문제인지 받아들일 문제인지 판단해야 했다
	- 확인 끝낸 곡을 다시 넣으면 또 걸러져 번거로웠고, 검사를 매번 할지 고르게 할지 정해야 했다
	- 에너지 1~5에 뭘 넣어야 할지 기준이 안 서서, 208곡을 손으로 다 매기는 대신 자동으로 깔 방법을 정해야 했다
	- 자동으로 잰 빠르기가 잔잔한 곡을 두 배로 잡아 활기찬 곡으로 분류되는 게 있어, 어디까지 믿고 어디부터 손볼지 정해야 했다
	- 부족한 장르를 그냥 채우는 게 아니라 누가 룸톤을 쓸지에서 역산해야 비율이 정해졌다
- MiniMacro
	- hover 메뉴는 클릭 좌표만 재생해서는 재현이 안 돼, 이동·대기·클릭을 어떻게 나눌지 정해야 했다
	- 듀얼 모니터에서 녹화한 곳과 다른 위치가 눌려, 녹화가 문제인지 재생이 문제인지 갈라내야 했다

## 배운 점

- 메트로놈 Simple Metronome
	- 스토어 설명은 앱 이름을 반복하는 게 아니라 기능·이점을 앞세워야 검색 노출·설치 전환에 도움이 된다
- 룸톤 Roomtone TIL 4로 정리
	- 프로그램을 곡마다 새로 부르면 무거운 준비(모델 로드)를 매번 반복하니, 한 번에 모아 부르면 준비는 한 번만 한다
	- 그래픽카드 가속은 엔비디아 계열만 되고, 있으면 자동으로 쓰고 없으면 CPU로 떨어지게 둔다
	- 곡의 빠르기는 자동으로 잴 수 있으나 두 배로 잘못 잡는 일이 흔해, 잔잔한 곡 위주면 높은 값을 접어 바로잡는다
	- 자동으로 매긴 값은 "초기값"이고 사람이 확정하는 구조로 두면 손으로 다 하지 않아도 되고 자동의 오차도 감당된다
	- 부족한 걸 채울 땐 빈칸이 아니라 수요(사업군)에서 역산한다
- MiniMacro TIL 1로 정리
	- 프로그램의 화면 배율 인식(DPI)은 처음 한 번만 정해져서, 라이브러리가 먼저 설정해 버리면 뒤에 한 설정은 조용히 무시된다
	- 전역 입력 후킹이 주는 좌표는 항상 물리 픽셀이라, 실행 쪽 좌표 해석과 일치시켜야 듀얼 모니터에서 안 어긋난다
	- 커서를 경로로 움직이면 도중에 hover 메뉴가 닫히니 좌표로 순간이동한다
	- 한글은 키 입력으로 못 넣고 클립보드 붙여넣기로 우회한다
	- 자동 입력 툴은 재생 중 마우스를 계속 빼앗으므로 화면 밖 비상 정지(ESC·모서리)를 처음부터 설계해야 한다
