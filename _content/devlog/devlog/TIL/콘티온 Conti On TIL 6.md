콘티 편집 화면에 하루 동안 여러 개선을 붙였다. 성격이 다른 넷을 한데 정리한다 — 그룹 경계, 터치 이동, 구분 필수, 내보내기 미리보기.

---

## 평면 리스트에서 "그룹 밖"을 표현하기

콘티 항목은 평면 리스트에 구분자(그룹 머리글)를 섞는 구조다. 그룹은 "구분자 다음부터 다음 구분자 전까지의 곡"이라, 맨 끝에 곡을 넣으면 항상 마지막 그룹에 딸려 들어간다 — 그룹 밖에 둘 방법이 없었다.

위치로만 소속이 정해지는 구조에서 "그룹 밖"을 표현하려면, 그룹을 끊는 표시가 필요하다. 빈 텍스트 구분자를 "그룹 밖 경계"로 쓰기로 했다. 이미 있는 직렬화(데이터를 저장·전송용 문자열로 바꾸기, 구분자=separator)를 그대로 타서 스키마 변경이 없다.

```ts
// 빈 텍스트 그룹은 "그룹 밖" 경계 — 이 뒤 곡은 어느 그룹에도 안 든다.
const isBreak = (it: ContiItem) => it.type === "group" && it.text.trim() === "";
```

문제는 경계가 쓸모없어지는 경우(그룹을 안 닫거나, 뒤에 곡이 없음)다. 저장할 때마다 그런 경계를 걸러내는 정규화(데이터를 일관된 형태로 다듬기)를 한 곳에 두고 모든 편집이 거치게 했다.

```ts
function normalizeBreaks(items: ContiItem[]): ContiItem[] {
  const out: ContiItem[] = [];
  let open = false; // 이름 있는 그룹 안인가
  for (let k = 0; k < items.length; k++) {
    const it = items[k];
    if (isBreak(it)) {
      if (!open || items[k + 1]?.type !== "song") continue; // 닫을 게 없거나 뒤에 곡 없음 → 버림
      open = false;
    } else if (it.type === "group") open = true;
    out.push(it);
  }
  return out;
}
```

경계는 화면에선 점선 한 줄로만 보여주고(라벨·버튼 없이), 복사·PPT 내보내기에선 제외한다 — 데이터엔 있지만 결과물엔 안 나가는 표식이다.

## 터치에서 순서를 바꾸는 다른 방법

iPad에서 콘티 순서를 못 바꾼다는 얘기가 나왔다. 원인은 근본적이었다 — HTML5 네이티브 드래그(`draggable`/`dataTransfer`)는 iOS·iPadOS에서 터치로 드래그 이벤트를 만들어내지 않는다. 마우스에서만 되는 것이었고, 순서 변경엔 드래그 말고 다른 길이 없었다.

선택지는 셋이었다. 드래그 라이브러리(dnd-kit) 도입, 포인터 이벤트(마우스·터치를 하나로 다루는 입력)로 직접 구현, 버튼식 대안. 데스크톱 드래그는 멀쩡히 도는데 그걸 걷어내고 큰 라이브러리로 갈아엎는 건 위험 대비 이득이 적었다. 그래서 데스크톱 드래그는 그대로 두고, 터치용으로 버튼 경로를 얹었다.

"위험 대비 이득이 적다"를 구체적으로 적어 둔다 — 나중에 다시 저울질할 때 쓰려고. 터치 드래그 자체는 포인터 이벤트나 dnd-kit으로 얼마든지 되지만(이 앱의 색 슬라이더가 포인터 이벤트로 터치까지 된다), 콘티 드래그는 단순 리스트가 아니다. 그룹(블록 통째 이동)·그룹 밖 경계·왼쪽 라이브러리에서 콘티로 끌어넣는 크로스 드래그·삽입 위치선·자동 스크롤이 얽혀 있어 라이브러리로 바꾸면 전면 재작성이다. 거기에 새 의존성이 붙고(번들·보안 검토), 터치에선 "끌어 옮기기"와 "화면 스크롤"이 같은 끌기 제스처라 롱프레스·`touch-action`으로 구분하는 튜닝이 필요하다. 자동 테스트가 없어 회귀는 iPad 실기기에서만 잡힌다. 잘 도는 데스크톱 경로를 걷어내면서 이 비용을 다 치를 만큼 급하지 않아, 통일(dnd-kit)은 미뤘다.

- 각 항목 왼쪽 그립(⠿) 자리에 선택 라디오를 둔다(하나만 선택).
- 리스트 위 공용 툴바 한 세트(위로·아래로·그룹 넣기/빼기)가 선택된 항목에 작용한다. 항목마다 버튼을 달지 않는다.
- 그룹 머리글을 고르면 블록째, 곡을 고르면 한 칸 이동.

그룹 소속은 어차피 위치로 갈리므로(경계를 넘으면 빠진다), 넣기/빼기는 한 버튼이 상황에 따라 라벨과 동작을 바꾸는 토글로 만들었다.

```tsx
{selCanToggle && (
  <button onClick={() => onToggleGroup(selectedUid)}>
    {selInGroup ? "그룹 빼기" : "그룹 넣기"}
  </button>
)}
```

곁들여, 그룹 이름이 길면 두 줄까지 두고 그 이상은 말줄임했다. flex 항목이라 `min-width: 0`이 없으면 말줄임이 안 걸리는 게 함정이었다.

```css
.conti-group-title {
  min-width: 0; /* flex 항목이라 이게 없으면 말줄임이 안 걸린다 */
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

## 구분을 필수로, 그런데 DB가 아니라 앱에서

곡의 구분(카테고리)을 필수로 만들고, 애매한 곡을 담을 catch-all을 두기로 했다. 그런데 예배 순서지엔 이미 '기타'가 있었다. 찬양에도 '기타'를 넣으려니 이름이 겹쳤다.

카테고리 이름은 전역 UNIQUE이고, 곡은 구분을 이름 문자열로 참조해 대분류(major)를 그 이름으로 역추적한다. 이름이 두 대분류에 겹치면 그 곡이 찬양인지 순서인지 판정이 모호해진다. 그래서 찬양 catch-all은 '그 외'로 이름을 갈랐다.

"DB에서 구분 required"를 물리 `NOT NULL`로 걸려다 멈췄다. SQLite는 기존 컬럼에 NOT NULL을 추가하려면 테이블을 통째로 재생성해야 하는데, 이 테이블은 다른 테이블들이 FK로 참조한다(콘티 항목의 곡 참조 등). 재생성하면 그 참조가 끊기거나 널이 될 위험이 프로덕션에 있다.

그래서 "필수"를 물리 제약이 아니라 앱 계층에서 보장했다.

```ts
function validate(body: SongInput): string | null {
  if (!body.title?.trim()) return "title_required";
  if (!body.lyrics?.trim()) return "lyrics_required";
  if (!body.hymn_type?.trim()) return "hymn_type_required"; // 구분 필수
  return null;
}
```

여기에 기존 데이터 정리 마이그레이션(빈칸/NULL → CCM, '없음' → '그 외', '없음' 카테고리 삭제)을 더하면, 새로 빈 구분이 안 생기고 옛 빈 값도 사라진다. 물리 제약 없이도 사실상 required가 된다. 물리 NOT NULL은 실익 대비 위험이 커서 백로그로 남겼다.

## 미리보기와 실제 PPT를 어긋나지 않게

PPT를 뽑아야만 결과를 볼 수 있었다. 내보내기 전에 슬라이드 미리보기를 넣기로 했는데, 미리보기가 실제 결과와 다르면 오히려 못 믿게 된다. 그래서 "무슨 슬라이드가 어떤 순서로, 무슨 텍스트인지"를 만드는 로직을 순수 함수(같은 입력이면 항상 같은 출력, 바깥을 안 건드리는 함수) 하나로 모으고, 미리보기와 pptx 생성이 그 하나를 공유하게 했다.

```ts
// 미리보기와 pptx가 이 한 시퀀스를 공유 → 서로 어긋나지 않는다
export function contiSlides(items: ContiExportItem[], blankBetween: boolean): SlideDesc[]
```

pptx 생성 쪽(`createDeck`)은 곡을 통째로 그리던 `addSong`을 `addTitle`·`addLyric`로 쪼개, 서술자 종류대로 부르게 바꿨다. 출력은 이전과 동일하다(제목 1장 + 가사 줄마다 1장, 그룹·빈 슬라이드 규칙 그대로).

미리보기 그림은 pptxgenjs 없이 직접 그린다. 슬라이드 좌표는 인치 기준이라, 실제 슬라이드(13.333in × 7.5in)를 화면 px로 옮기는 축척 상수를 공용 모듈로 뺐다(자막 편집 화면과 공유). 배경은 export가 쓰는 헬퍼(`makeBgDataUrl`)가 만든 data URL을 그대로 CSS 배경에 깔고, 자막 바·밴드 위치(`subtitle_dy` 미세조정 포함)·요소별 글꼴 크기를 템플릿에서 읽어 재현한다.

```ts
const ptToPx = (pt: number) => (pt / 72) * PX_PER_IN;
const bandTop = 6.3 * PX_PER_IN + ptToPx(tpl.subtitle_dy); // 밴드 y 6.3in + 미세조정
```

미리보기는 앱 최초의 전체화면 오버레이(화면 위에 덮어 띄우는 층, `position: fixed` 딤 배경)로 띄우고, 배경 클릭으로 닫되 패널에선 `stopPropagation`으로 막았다. 내보내기는 이미 resolve해 둔 항목을 그대로 넘겨 재조회하지 않는다.

> 한계: 브라우저 미리보기의 자막 글꼴은 재생 PC에 설치된 글꼴을 못 쓰면 근사치로 보이고, 긴 줄은 실제 PPT에서만 자동 축소된다. 오버레이 상단에 그 안내를 붙였다.

그런데 미리보기에서 자막 바 이미지만 깨져 나왔다. 이 앱은 자막 바 이미지를 base64로 들고 있는데, 그 base64를 pptxgenjs에 넘길 땐 `data:` 접두사를 뗀 형태(`image/png;base64,...`)로 준다 — pptxgenjs가 그 규격을 받기 때문이다. 그 값을 그대로 HTML `<img src>`에 넣으니 브라우저가 못 읽어 깨진 거였다. 같은 base64라도 쓰는 쪽 규격이 다르다.

```ts
// 미리보기 img엔 접두사를 다시 붙여야 한다
<img src={"data:" + bar.data} />
```

## 요약

- 평면 리스트에서 "그룹 밖"은 빈 구분자 경계로 표현하고, 쓸모없는 경계는 저장 시 한 곳에서 정규화한다.
- 터치에서 안 되는 드래그는 큰 라이브러리로 갈아엎기 전에, 선택(라디오) + 공용 버튼이라는 다른 경로를 얹는 게 위험이 적다. 데스크톱 경로는 건드리지 않는다.
- SQLite에서 기존 컬럼 NOT NULL은 테이블 재생성이 필요하고 FK 참조가 있으면 위험하다. "필수"는 앱 검증 + 데이터 정리로도 사실상 보장된다.
- 미리보기가 결과와 어긋나면 못 믿는다. 순서·내용을 만드는 로직을 순수 함수 하나로 모아 미리보기와 실제 생성이 공유하게 한다.
- 같은 base64 이미지라도 쓰는 쪽 규격이 다르다 — pptxgenjs는 `data:` 없이, HTML `<img>`는 `data:` 붙여서.
