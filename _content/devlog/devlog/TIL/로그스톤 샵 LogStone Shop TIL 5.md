## 정적 호스팅의 함정

### 없는 경로가 404가 아니라 홈을 돌려준다

정적 호스팅(Cloudflare Pages)은 파일이 없는 경로를 요청받으면 오류를 주는 대신 상위의 `index.html`을 정상 응답으로 돌려주는 경우가 있다. 브라우저로 열면 "어라, 지웠는데 왜 열리지" 싶고, 기계가 읽으면 더 나쁘다.

이 함정을 이틀 새 두 곳에서 만났다.

- 제품 소개 페이지를 내렸는데 그 주소가 멀쩡히 열렸다 — 페이지 파일만 지웠으니 없어진 줄 알았는데 홈 내용이 응답하고 있었다.
- 광고 인증 파일(`app-ads.txt`)을 안 올린 상태에서, 광고 플랫폼이 그 주소를 읽고 홈 HTML을 인증 파일로 해석했다. 그래서 "파일은 설정됐는데 세부정보가 일치하지 않는다"는 진단이 나왔다. 아예 없는 것보다 헷갈리는 상태다.

교훈은 하나다 — 정적 사이트에서 경로를 내리거나 루트에 파일을 올릴 때는 배포 뒤 실제 응답을 확인한다. 상태 코드만 보면 둘 다 200이라 속는다. 본문 첫 줄과 `Content-Type`까지 봐야 한다.

```bash
curl -s https://example.com/app-ads.txt | head -c 80   # 본문이 HTML인지 평문인지
curl -sI https://example.com/app-ads.txt | grep -i content-type
```

### 임시로 닫을 땐 302, 영영 닫을 땐 301

페이지를 잠시 내릴 때 무엇을 응답할지 고를 수 있다. 셋의 뜻이 다르다.

- 404 — 이 주소는 없다. 검색엔진이 색인에서 지운다. 다시 열 계획이면 손해다.
- 301(영구 이동) — 주소가 바뀌었다. 색인이 새 주소로 넘어가고, 되돌려도 원래대로 돌아오는 데 시간이 걸린다.
- 302(임시 이동) — 잠깐 다른 곳을 보여준다. 원래 주소를 계속 들고 있는다.

출시 대기처럼 곧 되살릴 페이지는 302가 맞다. Cloudflare Pages에서는 `public/_redirects` 한 줄이면 된다.

```text
/sandrop/     /      302
/ko/sandrop/  /ko/   302
```

주의할 점은 규칙의 범위다. 위처럼 정확한 경로만 적으면 그 주소만 걸리고, 같은 폴더 아래의 다른 주소(`/sandrop/privacy/`)는 영향받지 않는다. 앱에 박혀 있거나 스토어에 제출한 주소가 그 아래 있다면 이 구분이 중요하다 — 와일드카드로 폴더째 잡으면 계약을 함께 끊는다.

## 광고 인증

### app-ads.txt는 도메인 주인의 선언이다

광고가 붙는 앱은 "이 앱의 광고 재고를 팔 권한이 있는 퍼블리셔가 누구인가"를 도메인으로 증명한다. 앱 스토어 등록정보에 적힌 개발자 웹사이트를 광고 플랫폼이 찾아가서, 루트의 `app-ads.txt`에 자기 퍼블리셔 아이디가 적혀 있는지 확인하는 방식이다.

```text
google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0
```

알아 둘 것 몇 가지.

- 계정 단위다 — 한 줄이면 그 퍼블리셔 계정의 모든 앱이 커버된다. 앱마다 줄을 늘릴 필요가 없다.
- 위치는 루트여야 한다 — 언어 경로에 두는 건 의미가 없다. 확장자가 `.txt`라 형식은 대개 알아서 평문으로 나간다.
- 없으면 손해가 실재한다 — 일부 광고 구매자가 인증되지 않은 재고를 입찰에서 제외한다. 신규 앱이라 원래도 재고가 잘 안 붙는 시기에는 원인 구분까지 어려워진다.
- 스토어에 적은 웹사이트 주소와 파일을 올린 도메인이 같아야 한다. 이건 콘솔 설정이라 코드에서 확인할 수 없는 항목이다.

## 검색 노출

### 사이트맵은 링크로 닿지 않는 페이지를 위한 것이다

크롤러는 링크를 따라다니며 페이지를 발견한다. 그래서 사이트 안에서 아무도 링크하지 않는 페이지는 존재해도 찾아오지 못한다. 우리 샵이 딱 그랬다.

- 페이지는 스물두 개인데 홈에서 링크로 닿는 건 제품 세 개뿐이다.
- 제품별 방침·약관 열두 개는 푸터에 통합본만 걸려 있어서, `/sandrop/privacy/` 같은 주소는 사이트 어디에서도 링크되지 않는다. 앱과 스토어에서만 쓰는 주소라 그렇다.
- 한국어 페이지도 언어 전환 버튼으로만 닿는다.

사이트맵은 "이 사이트에 이런 주소들이 있다"를 한 파일로 넘기는 목록이라 이 구멍을 메운다. 정적 사이트 생성기에는 대개 공식 통합이 있어서, 붙여 두면 페이지가 늘 때마다 자동으로 반영된다.

```js
// astro.config.mjs — i18n을 주면 각 주소에 언어별 대체 링크가 함께 들어간다
integrations: [
  sitemap({ i18n: { defaultLocale: 'en', locales: { en: 'en', ko: 'ko' } } }),
]
```

언어별 대체 링크(hreflang)가 왜 좋냐면, 같은 내용의 영어·한국어 페이지를 검색엔진이 중복으로 보지 않고 한 쌍으로 이해하기 때문이다. 그러면 방문자의 언어에 맞는 쪽이 결과에 나온다.

### robots.txt는 없는 것보다 잘못 있는 게 나쁘다

robots.txt는 크롤러에게 주는 규칙 파일이고, 사이트맵 주소를 여기 적어 두면 제출하지 않아도 발견된다.

```text
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap-index.xml
```

여기서도 앞서 배운 함정이 그대로 반복됐다. 파일을 안 올린 상태에서 그 주소를 열면 홈 HTML이 정상 응답으로 돌아온다. 크롤러는 그걸 규칙 파일로 파싱하려다 실패한다 — 규칙이 없는 것보다 헷갈리는 상태다. 사이트맵도 마찬가지여서, 올린 뒤에는 XML이 실제로 나오는지(형식이 `application/xml`인지) 확인하는 게 맞다.

검색 콘솔 제출은 별개다. 사이트맵을 올려 두면 언젠가는 발견되지만, 콘솔에 직접 제출하면 색인 상태와 오류를 화면에서 볼 수 있어 진단이 빨라진다.

## 이미지 재사용

### 스토어에 올린 이미지를 사이트에 그대로 쓴다

앱 스토어 등록정보용으로 만든 소개 이미지는 사이트에서도 쓸 수 있다. 다시 만들지 않는 편이 낫다 — 문구가 갈라지면 어느 쪽이 최신인지 알 수 없게 된다. 원본이 어디인지 정해 두고 그것만 쓰는 게 낫다.

이번에 배운 실무 포인트 셋.

- 문구가 한국어와 영어로 함께 박힌 이미지면 언어별 페이지 양쪽에 그대로 쓸 수 있다. 대체 텍스트(alt)만 언어별로 갈라 주면 된다.
- 이미 기기 목업 형태로 만들어진 이미지에는 액자를 덧대지 않는다. 페이지에서 다시 폰 프레임을 씌우면 프레임 안에 프레임이 된다.
- 스토어용 원본은 무겁다. 1080×1920 PNG가 장당 0.6~1MB인데, 빌드 시 WebP로 변환하면 20~30KB로 떨어진다. 세 장을 얹어도 100KB가 안 된다.

```astro
<Image src={shot} alt={t('sd.shots.a1')} format="webp" width={620} quality={80} />
```

## 배포 확인

### 옛 응답이 오면 캐시인지 배포 지연인지부터 가른다

파일을 올리고 바로 확인했더니 여전히 옛 응답이 왔다. 이때 코드를 의심하기 전에 두 가지를 갈라야 한다.

- 배포가 아직 안 끝났다 — 빌드·전파에 1~2분 걸린다.
- 응답이 캐시돼 있다 — 특히 이전에 그 경로가 무언가를 정상 응답했다면 그게 남아 있을 수 있다.

가르는 방법은 간단하다. 호스팅이 주는 원 주소로 직접 조회해 보고(커스텀 도메인 앞단을 건너뛴다), 캐시 우회 요청을 함께 보내 비교한다.

```bash
curl -s https://myproject.pages.dev/app-ads.txt | head -c 80        # 원 주소
curl -s -H "Cache-Control: no-cache" "https://example.com/app-ads.txt?cb=$RANDOM"
curl -sI https://example.com/app-ads.txt | grep -i cf-cache-status  # DYNAMIC/HIT 확인
```

원 주소에서 새 내용이 보이는데 커스텀 도메인이 옛 내용이면 캐시나 전파 문제이고, 원 주소에서도 옛 내용이면 배포가 아직 안 끝난 것이다. 이번 건은 후자였고 잠시 뒤 정상이 됐다.
