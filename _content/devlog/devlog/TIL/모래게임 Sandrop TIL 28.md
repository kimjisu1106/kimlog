## 정보를 어디서 읽을까

### 만들기 전에 이미 파일에 있는지 본다

도안 검토 페이지에 "이 그림이 몇 탄인지"를 띄우고 싶었다. 처음엔 도안 목록에 레벨 번호를 적는 새 파일을 만들 생각을 했다.

그런데 레벨 파일 하나하나가 자기가 쓰는 도안 이름을 이미 들고 있었다. 방향만 뒤집으면 되는 일이었다.

```python
def _level_map() -> dict[str, list[int]]:
    """도안 이름 → 그 도안이 쓰인 레벨 번호."""
    out: dict[str, list[int]] = {}
    for f in sorted(os.listdir(LEVEL_DIR)):
        d = json.load(open(os.path.join(LEVEL_DIR, f), encoding="utf-8"))
        out.setdefault(d["name"], []).append(d["id"])
    return out
```

- 화면에 없는 정보를 새로 만들기 전에, 이미 어딘가에 있는 값을 뒤집어 읽으면 되는지 본다
- 파일 500개를 읽어도 순식간이다. "느릴 것 같다"는 짐작으로 새 파일을 만들면 관리할 것만 는다

---

### 원본이 하나면 매번 읽는 편이 안전하다

만든 매핑을 파일로 저장해 둘 수도 있었다. 그러면 레벨이 바뀌었을 때 저장본을 같이 고쳐야 한다.

저장하지 않고 페이지를 만들 때마다 읽게 뒀다. 원본이 레벨 파일 하나뿐이라 어긋날 자리가 없다.

- 같은 사실을 두 곳에 두면 둘을 맞추는 일이 새로 생긴다
- 캐시는 읽는 비용이 실제로 아플 때 넣는다. 아프지 않은데 넣으면 비용 대신 버그가 남는다

---

## 배열 다루기

### 정렬은 원본을 제자리에서 바꾼다

레벨순으로 보여 주려고 정렬을 붙였다. 그런데 `sort()`는 새 배열을 돌려주는 게 아니라 받은 배열 자체를 뒤섞는다. 원본 목록에 바로 걸면 다른 화면의 순서까지 같이 바뀐다.

```js
if (mode === 'used')
  return all.filter(it => it.lv.length).sort((a, b) => a.lv[0] - b.lv[0]);
```

`filter()`가 먼저 새 배열을 만들어 주므로, 그 결과에 정렬을 거는 건 안전하다. 순서가 반대였다면 원본이 상했다.

- 원본을 바꾸는 함수와 새 값을 돌려주는 함수를 구분해 둔다. 이름만으로는 안 갈라진다
- 두 개를 이어 쓸 때는 앞의 것이 새 배열을 만들어 주는지 확인한다

---

### 선택칸을 다시 채울 때는 고른 값을 지킨다

출처 목록에 개수를 같이 적으려니, 목록이 바뀔 때마다 선택칸을 다시 채워야 했다. 그냥 비우고 채우면 사용자가 골라 둔 값이 매번 풀린다.

```js
sel.innerHTML = '';
add('', '전체 소스 (' + list.length + ')');
for (const k of Object.keys(cnt).sort()) add(k, k + ' (' + cnt[k] + ')');
sel.value = cnt[cur] ? cur : '';
```

고른 값이 새 목록에도 있으면 되돌리고, 없어졌으면 전체로 떨어뜨린다.

- 화면을 다시 그리는 코드는 사용자가 만들어 둔 상태를 지우기 쉽다. 다시 그리기 전에 무엇을 들고 있어야 하는지 먼저 센다
- "없어졌으면 어디로 가는가"까지 정해 둔다. 안 정하면 빈 값이 남아 아무것도 안 보이는 화면이 된다

---

### 입력칸을 늘리기 전에 있는 칸이 더 받을 수 있는지 본다

레벨 번호로도 찾고 싶었다. 번호 전용 입력칸을 새로 만들 수도 있었지만, 이름 검색칸이 이미 있었다.

```js
if (q && !item.name.toLowerCase().includes(q) && !lv.some(n => String(n) === q)) continue;
```

이름에 없으면 번호에서도 본다. 안내 문구만 "이름·레벨 검색"으로 바꿨다.

- 검색은 대개 "어느 칸에 넣을지"를 사용자가 고민하게 만들지 않는 편이 낫다
- 칸이 늘면 화면도 늘고 설명도 는다. 하나로 받을 수 있으면 하나로 받는다

## 전체를 생각하고 짠 코드

### 부분 재생성에서 빠지는 로직이 있다

이 게임에는 한국 도안 19종을 초반부터 일정 간격으로 흩어 놓는 코드가 따로 있다. 그런데 그 코드가 동결 모드(이미 만든 레벨은 손대지 않는 모드)에서는 통째로 건너뛴다.

```python
kr = [] if frozen else sorted(...)
```

동결 상태에서 전부 다시 흩으면 이미 만든 레벨과 부딪히니 맞는 동작이다. 그런데 레벨 하나만 지우고 다시 만들 때는 뜻이 달라진다 — 그 자리에 한국 도안이 다시 올 이유가 없어진다.

- 전체 생성만 상정하고 짠 조건이 부분 생성에서 다른 뜻이 되는지 본다. 조건 자체는 안 틀렸고 쓰임이 늘어난 것이다
- 특수 배치가 있는 자리는 목록으로 적어 둔다. "이 번호는 지우지 않는다"가 문서에 없으면 다음에 지운다

---

### 상태를 파일에서 읽으면 파일을 지우는 것이 곧 명령이 된다

특정 레벨만 다시 만드는 옵션이 필요할 줄 알았다. 그런데 동결 목록을 별도 파일이 아니라 폴더에 실제로 있는 파일에서 읽고 있었다.

```python
def _existing() -> dict[int, str]:
    """{레벨 번호: 도안 이름} — 이미 만들어져 있는 레벨."""
```

그러니 레벨 파일 하나를 지우면 그 번호는 저절로 "아직 안 만든 것"이 된다. 옵션을 안 만들어도 된다.

- 상태를 따로 적어 두는 대신 실물에서 읽으면, 실물을 건드리는 것이 그대로 조작 방법이 된다
- 별도 목록을 두면 실물과 목록이 어긋날 수 있다. 실물에서 읽으면 그럴 자리가 없다

## 되돌린 판단

### 이름만 빼면 다음에 또 빠진다

풀에서 제외한 도안 목록은 리뷰 차수마다 이유를 주석으로 달아 쌓아 온 것이다. 이번에 8종을 되살리면서 이름만 지우면, 다음 전수 리뷰 때 같은 눈으로 보고 또 뺀다.

```python
# 7차 리뷰에서 되살린 것 — 다시 빼지 않는다:
#   rabbit(토끼) u1f367(🍧) u1f415(🐕) ...
_EXCLUDED_SHAPES = frozenset({
```

- 판단을 뒤집을 때는 그 판단이 다시 나오는 것까지 막아야 끝난다
- 사람이 한 번 고른 것을 코드에 남기면, 다음 사람이 같은 질문을 안 받는다

---

### 목록에서 뺀 값은 주석에서도 뺀다

제외 목록의 주석은 무엇을 왜 뺐는지 나열하고 있었다. 이름을 뺀 줄의 주석을 그대로 두면, 목록에 없는 것이 설명에만 남는다.

```python
# 사무·문서 기호 💬 💭 💠 💱 ...      ← 💠는 이제 풀에 있다
```

- 목록과 그 목록을 설명하는 주석은 같이 고친다. 주석이 코드보다 오래 산다
- 항목이 하나 빠져 이유가 안 맞게 되면 이유도 고친다. "실루엣 애매·징그러움"에서 징그러운 것만 빠졌으면 제목도 줄인다

## 출시 운영

### 심사 중에도 저장소는 고쳐도 된다

심사는 이미 올린 설치 파일을 대상으로 진행되고, 저장소를 고치는 것과는 상관이 없다.

- 승인 나면 버전 번호만 올려 새 파일로 업데이트하면 된다
- 오히려 기다리는 동안이 다듬기 좋은 시간이다. 승인 직후 바로 낼 것을 쌓아 둘 수 있다

---

### 레벨을 다시 만들면 그림만 바뀌는 게 아니다

도안이 마음에 안 들어 그 레벨을 다시 만들면, 그림만 갈리는 게 아니라 배치·벽·기믹·난이도가 전부 새로 뽑힌다.

다행히 진행 상황은 레벨 번호로 기록돼 있다. 이미 깬 사람은 깬 채로 남고 그림만 달라진다.

- 무엇이 같이 바뀌는지 먼저 세고 나서 바꾼다. "그림만 바꾸기"가 되는 구조인지 아닌지가 갈린다
- 저장 방식이 무엇을 기준으로 삼는지 알면 바꿔도 되는 범위가 정해진다
