파티클 통일 재작업·공연 출력 창 버그·0.1.5 출시에서 나온 것들. 앞선 TIL 43에서 이어진다.

## 파티클 물리

### 속도를 크기에서 떼어내기 — 속도와 항력을 같이 키운다

항력 아래에서 도달 거리는 `도달 = 초기속도 ÷ 항력`이다(감쇠가 다 되면 이 값에서 멈춘다). 그래서 속도를 올리면 도달도 같이 커진다 — 방사형 개화가 속도를 올릴 때 돔이 통째로 커진 이유다.

속도와 크기를 분리하려면, 도달은 폭·높이로 고정하고 속도와 항력을 같은 비율로 곱한다.

```ts
// 도달 = v/drag. v와 drag를 같은 s배 하면 도달은 그대로, 시간만 1/s로 압축된다.
phys.vx = dirX * Wreach * dragBase * speed;
phys.vy = dirY * Hreach * dragBase * speed;
phys.drag = dragBase * speed;
phys.lifeSec /= speed; // 더 빨리 터지고 사라짐 — 크기는 그대로
```

이러면 속도는 "얼마나 빨리 터지고 사라지나"만 바꾸고 크기는 안 건드린다.

### 방사형 반원 돔 — 폭·높이를 두 축으로 독립 제어

방사형은 위쪽 반원으로 퍼진다. 이 반원을 가로 반경(폭)·세로 반경(높이)으로 나눠, 각 파티클의 단위 방향 벡터에 축별 도달을 곱한다. 폭·높이가 균형이면 반원, 높이를 키우면 세로로 솟는 돔, 폭을 키우면 옆으로 퍼진다.

### apex를 캡할 땐 가로도 같은 비율로 줄인다

분수는 중력 포물선이라 발사 속도가 너무 크면 화면 밖으로 솟는다. 최고점(apex)을 목표 높이로 캡하는데, 세로 속도만 캡하면 가로는 그대로라 속도를 올릴수록 옆으로 눕는다.

```ts
// ❌ 세로만 캡 → 속도↑에서 발사각이 눕는다
if (-vy > vMax) vy = -vMax;

// ✅ 캡한 비율만큼 가로도 줄여 발사각 유지
if (-vy > vMax) {
  vx *= vMax / -vy;
  vy = -vMax;
}
```

### "폭 최소 = 건반 너비"는 흔들림도 폭에 연동해야 한다

스폰 위치를 눌린 건반 너비로 좁혀도, 좌우 흔들림(sway)이 폭과 무관하게 살아 있으면 파티클이 그 밖으로 퍼진다. 그래서 흔들림 진폭도 폭에 연동한다 — 폭이 0이면 흔들림도 0이라 실제로 건반 너비에 갇힌다.

## 코드 정리

### 루프 불변값은 루프 밖으로, 중복 상수는 하나로

파티클을 개수만큼 도는 루프 안에서 `params`만으로 정해지는 값(도달 목표·폭 배율 등)을 매번 다시 계산하고 있었다. 루프 앞에서 한 번만 구하면 "이건 공통값 / 이건 파티클별"이 분리돼 읽기 쉬워진다.

또 같은 값을 두 이름으로 두던 것(`topFrac`와 모듈 상수 `SPAWN_Y`가 둘 다 `1 - KEYBOARD_H`)을 하나로 합쳐, 스폰 높이와 도달 기준 높이가 같은 값임이 코드로 드러나게 했다.

## UI 설계

### 컨트롤 노출은 "무엇을 쓰는지"를 데이터로 선언하고 읽는다

모션마다 쓰는 컨트롤이 다르다(나선엔 회전 반경, 불꽃엔 폭 없음). 이걸 모션마다 `.hidden = ...`으로 나열하니 틀리기 쉬웠다(안 쓰는 모래 높이가 떠 있던 것도 이래서다).

완전 자동은 불가능하다 — 어떤 모션이 무엇을 쓰는지는 코드가 못 정하는 도메인 지식이다. 대신 그 지식을 한 곳에 선언하고 UI는 읽기만 하게 한다.

```ts
// 모션 정의에 "쓰는 컨트롤"을 같이 — 단일 출처
{ value: "spiral", label: "나선", uses: ["spiralRadius", "spread", "coilPitch"] }
{ value: "sand",   label: "모래", uses: ["width"] }
// 표시는 이 목록만 읽는다
for (const row of motionRows) row.hidden = !uses.includes(row.key);
```

새 모션·컨트롤이 생기면 이 목록 한 줄만 고치면 되고, 표시 로직은 안 건드린다. 틀릴 여지가 두 곳(물리·UI)에서 한 곳으로 준다.

## 창 간 상태 동기화

### 갓 연 창에 바로 보낸 이벤트는 사라진다 — ready 핸드셰이크

공연 출력 창(두 번째 창)은 본 창과 프레임을 공유하지 않고 이벤트만 받아 따로 그린다. 창을 만들자마자 배경을 보냈더니, 창이 아직 리스너를 안 붙인 상태라 그 이벤트가 그냥 없어졌다(emit은 받는 리스너가 없으면 버려진다).

받는 쪽이 준비를 마치고 신호를 보내면, 보내는 쪽이 그때 현재 상태를 보낸다.

```ts
// 출력 창: 리스너 다 붙인 뒤
void emit("kb:ready", {});
// 본 창: ready 받으면 현재 배경을 보낸다
void listen("kb:ready", () => emitBg());
```

이러면 창이 뜨는 타이밍에 안 휘둘리고 첫 화면부터 상태가 맞는다.

## 릴리스 운영

### Tauri 서명 키 env는 "파일 경로 또는 키 내용"

`TAURI_SIGNING_PRIVATE_KEY`에 파일 경로를 줬는데 그 경로에 파일이 없으면, Tauri는 값을 base64 키 내용으로 해석해 디코드한다. 그래서 잘못된 경로(`C:\...`)를 주면 `C` 다음 `:`에서 "invalid base64" 에러가 난다 — 경로가 아니라 내용으로 읽힌 신호다. 실제로 존재하는 경로를 주거나, 파일 내용을 직접 넣으면 된다.

### 콘텐츠 기반 서명은 파일명과 무관하다

minisign 서명은 파일 내용으로 만들어져서, 같은 파일을 다른 이름으로 올려도 검증된다. 그래서 같은 버전을 다시 빌드·재업로드할 때도 파일명은 그대로 두고 `latest.json`의 signature만 새 것으로 갈면 된다.

### 다운로드 시작 전 공백을 채운다

자동 업데이트에서 확인을 누르면 다운로드가 연결될 때까지(리다이렉트 해석 등) 진행 이벤트가 안 온다. 그 사이 아무 표시가 없으면 멈춘 것처럼 보인다. 확인 직후 바로 "준비 중" 오버레이를 띄우고, 다운로드가 시작되면 진행바로 바꾼다 — 저장 버튼처럼 누르는 즉시 반응하게.
