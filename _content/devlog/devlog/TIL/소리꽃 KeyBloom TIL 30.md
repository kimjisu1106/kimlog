유료화를 붙이기 전에 뼈대부터 세웠다. "무료냐 유료냐"를 어떻게 켜고 끄는지, 그 판정을 어디에 두는지, 라이선스가 진짜인지 어떻게 안전하게 확인하는지.

---

## 잠금은 상수가 아니라 함수여야 켤 수 있다

무료 잠금(워터마크·4K·알파)이 `IS_FREE = true` 같은 빌드 상수로 박혀 있으면, 산 사람에게만 풀어줄 방법이 없다. 값이 컴파일에 고정이라.

그래서 상수를 없애고 판정을 함수로 바꿨다. 잠금이 걸린 모든 곳이 이 함수 하나를 본다.

```ts
// 웹은 항상 무료(네이티브 아님), 네이티브 + 유효 라이선스일 때만 PRO
export function isPro(): boolean {
  return IS_NATIVE && licensed;
}
// 게이팅은 전부 !isPro()로 — 워터마크·4K·알파 잠금 판정이 한 곳에 모임
if (!isPro()) drawWatermark(ctx, view);
```

값이 아니라 함수라 런타임에 라이선스가 활성화되면 즉시 풀린다. 웹은 `IS_NATIVE`가 거짓이라 이 함수가 늘 거짓 → 웹은 언제나 무료로 유지된다.

## 라이선스 검증 시크릿은 앱에 두면 안 된다

결제사(Creem)의 라이선스 검증 API는 시크릿 키가 필요하다. 이걸 앱(프론트)에 넣으면 누구나 열어 볼 수 있어, 검증을 위조하거나 남의 키를 활성화할 수 있다.

그래서 시크릿을 클라우드(Cloudflare Worker)에 두고, 앱은 그 워커한테만 물어보게 한다.

```text
앱  →  Cloudflare Worker(시크릿 보관)  →  Creem 검증 API
        └ 앱 번들·저장소엔 키가 절대 안 들어감
```

앱은 "이 키 맞아?"만 워커에 묻고, 워커가 시크릿으로 Creem에 확인해 결과만 돌려준다. 앱 대신 물어봐 주는 이런 중계 서버가 프록시다. 오프라인 네이티브라 최초 1회 온라인 활성화 → 로컬 토큰 저장 → 가끔 재확인 + 무네트워크 유예로 설계했다.

## 결제사는 언제든 갈아끼울 수 있어야 한다

신생 결제사는 인수·폐업 위험이 있다. 그래서 라이선스 확인 로직을 인터페이스로 떼어 감쌌다. 활성화·검증·해제 같은 동작만 규격으로 두고, 특정 결제사(Creem) 구현은 그 뒤에 숨긴다.

- 배운 점: 나중에 다른 결제사로 바꿔도 게이트(조건에 따라 기능을 잠그고 여는 것) 호출부인 `!isPro()`는 그대로 두고 뒤쪽 구현만 교체하면 됨. "값싼 보험"

> 참고 — MoR(Merchant of Record) = 결제 대행이 판매자로 나서서 전 세계 세금·부가세를 대신 처리하고, 라이선스 키 발급·검증 API까지 주는 방식. 솔로가 해외 판매할 때 세금 처리를 안 해도 되는 게 큼.

## 요약

- 무료/유료 잠금은 빌드 상수가 아니라 판정 함수(`isPro()`)로 둬야 라이선스로 켤 수 있다.
- 검증 시크릿은 앱에 두지 말고 클라우드 프록시(Worker) 에 숨겨 앱은 그 서버에만 묻는다.
- 결제사 구현은 인터페이스로 감싸 교체 가능하게 — 게이트 호출부는 불변.
