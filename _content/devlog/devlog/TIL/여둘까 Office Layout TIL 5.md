캐드 파일을 열 수 있냐는 질문 하나로 시작했는데, 답이 "라이브러리가 없다"가 아니라 "치를 값이 너무 크다"였다. 파일 입력을 막는 방법, 포맷과 라이선스를 읽는 법, 그리고 안 하기로 한 결정을 남기는 법을 정리한다.

---

## 파일 입력 다루기

### accept 속성은 강제가 아니라 필터다

`<input type="file" accept="...">`는 파일 선택창의 기본 필터를 정할 뿐이다. 사용자가 선택창 우하단에서 "모든 파일"로 바꾸면 어떤 확장자든 고를 수 있고, 드래그 앤 드롭으로 넣으면 아예 거치지도 않는다.

```html
<!-- 이건 "편의"지 "보안"이나 "검증"이 아니다 -->
<input type="file" id="bgUpload" accept="image/*,application/pdf,.pdf" hidden>
```

소리꽃 KeyBloom TIL 17에서 정리한 "게이팅은 UI와 실행 경로 두 겹으로"와 정확히 같은 구조다. `option`에 `disabled`를 걸어도 개발자도구로 지우면 뚫리니 실행 함수 안에 가드가 또 있어야 했던 것처럼, `accept`도 표시일 뿐이고 실제 판정은 핸들러 안에서 해야 한다.

### 가드는 핸들러 맨 앞에

읽기 시작한 뒤에 되돌리는 것보다, 읽기 전에 끊는 게 항상 간단하다.

```js
document.getElementById("bgUpload").onchange = async (e) => {
  const file = e.target.files[0];
  if (!file) return;

  // 읽는 코드보다 먼저
  if (/\.(dwg|dxf)$/i.test(file.name)) {
    alert("캐드 파일(.dwg/.dxf)은 직접 열 수 없습니다.\n\n무료 캐드 뷰어(DWG TrueView, 오토데스크 뷰어 등)로 도면을 연 뒤 PDF로 인쇄·내보내고, 그 PDF를 올려주세요.");
    e.target.value = "";
    return;
  }
  // ... 이 아래는 열 수 있는 파일만 도달
};
```

정규식에 `i` 플래그를 붙이는 걸 빼먹으면 `도면.DWG`가 그대로 통과한다. 윈도우에서 대문자 확장자는 흔하다.

### file.type만 믿으면 안 된다

`File.type`은 브라우저가 추측한 MIME 타입이라 빈 문자열로 오는 경우가 있다. 등록되지 않은 확장자거나, OS가 매핑을 모르면 그렇다. 그래서 기존 PDF 판정도 두 가지를 `||`로 묶어 놨다.

```js
// MIME이 비어 와도 확장자로 건짐
const isPdf = file.type === "application/pdf" || /\.pdf$/i.test(file.name);
```

반대로 확장자만 믿는 것도 위험하다. 둘 다 보는 게 맞고, 어느 쪽도 "내용이 진짜 그 포맷"임을 보장하진 않는다(그건 매직 넘버를 읽어야 안다).

### input.value를 비워야 같은 파일을 다시 고를 수 있다

`change` 이벤트는 값이 바뀔 때만 뜬다. 같은 파일을 다시 고르면 값이 그대로라 이벤트가 안 뜨고, 사용자 입장에선 클릭했는데 아무 일도 안 일어난다.

```js
e.target.value = "";   // 다음 선택을 위해 초기화
```

가드로 일찍 `return` 할 때도 이걸 빼먹으면 안 된다. 안내를 보고 같은 파일을 다시 시도하는 게 오히려 자연스러운 흐름인데, 그때 조용해진다.

### 조용히 실패하는 경로를 조심할 것

가드를 넣기 전에 dwg를 고르면 이미지 분기로 흘러갔다.

```js
const reader = new FileReader();
reader.onload = () => applyBackground(reader.result);
reader.readAsDataURL(file);
```

`FileReader`는 바이너리가 뭐든 성공한다 — dataURL로 바꾸는 것뿐이라 내용을 판단하지 않는다. 그 다음 이미지 로드에서 실패하는데, 이건 예외를 던지지 않고 `error` 이벤트로만 알린다. 아무도 안 듣고 있으면 `try/catch`에도 안 걸린다. 결과는 "에러 없음 + 아무 변화 없음"이고, 사용자에겐 앱이 고장 난 것으로 보인다.

습관만들기 Pawbit에서 `errorBuilder`가 없는 이미지를 조용히 정상 이미지로 대체하던 것과 같은 함정이다. 실패가 화면에 안 드러나면 없는 버그가 되는 게 아니라, 못 찾는 버그가 된다.

## 포맷과 라이선스

### DWG를 브라우저에서 못 읽는 이유

DWG는 Autodesk의 독점 바이너리 포맷이고 공개 규격이 없다. 게다가 버전(AC1015 / AC1024 / AC1032 …)마다 내부 구조가 달라서, 리버스 엔지니어링으로 만든 파서도 특정 버전에서만 동작하는 일이 흔하다. "열리는 파일과 안 열리는 파일이 섞이는" 지원은 안 하느니만 못하다.

### GPL은 전염된다

GPL(GNU General Public License)은 오픈소스 라이선스의 한 종류다. 라이선스는 "이 코드를 가져다 쓰려면 이 조건을 지켜라"는 사용 약관인데, GPL은 그 조건이 유독 강하다 — GPL 코드를 한 조각이라도 가져다 쓰고 배포하면, 그걸 포함한 내 프로그램 전체의 소스도 똑같이 공개해야 한다. 그래서 "물든다 / 전염된다"고 부른다.

브라우저에서 DWG를 읽을 유일한 현실적 수단은 LibreDWG라는 라이브러리를 WASM(브라우저에서 도는 형태)으로 포팅한 것인데, 이 LibreDWG가 GPL-3.0이다.

| 라이선스 | 내 코드에 미치는 영향 |
| --- | --- |
| MIT / Apache-2.0 | 저작권 표시만 하면 됨. 내 코드는 비공개 가능 |
| LGPL | 동적 링크면 내 코드는 그대로. 정적 링크·번들이면 조건 붙음 |
| GPL-3.0 | 링크한 저작물 전체가 GPL로 배포돼야 함 (전염성) |

여둘까는 빌드 없이 CDN으로 라이브러리를 붙이는 정적 웹앱이라, WASM을 얹는 순간 앱 전체가 GPL 배포 대상이 된다. 기능 하나 때문에 프로젝트 전체의 라이선스를 바꾸는 건 값이 안 맞았다. 라이브러리를 고를 때 "동작하는가" 다음에 오는 질문이 "무슨 라이선스인가"여야 한다는 걸 배웠다. 모래게임 Sandrop에서 폰트를 Apache 2.0으로 알고 있다가 실제로는 OFL이라 앱 안 고지가 틀려 있던 것과 같은 종류의 실수다.

### DXF는 왜 다른가

같은 Autodesk 계열인데 DXF는 성격이 완전히 다르다.

- Autodesk가 공개한 교환용 규격이다
- 텍스트 기반이라 파싱이 단순하다. 그룹 코드와 값이 한 줄씩 번갈아 나오는 구조
- MIT 라이선스 파서(`dxf-parser`, `bjnortier/dxf` 등)가 있고 CDN으로 붙일 수 있어 "빌드 없음" 제약도 안 깨진다
- 무엇보다 도면 안에 실제 단위가 들어 있다 (`$INSUNITS`, `$MEASUREMENT` 같은 헤더 변수)

마지막 항목이 이 도구엔 특히 크다. 여둘까는 지금 사용자가 벽 한 변을 클릭해 실제 길이를 입력하는 축척 보정을 반드시 거쳐야 하는데, DXF를 읽으면 `pxPerMm`을 도면에서 그냥 꺼낼 수 있다. 가장 귀찮은 단계가 통째로 사라진다.

래스터(PNG·PDF 이미지)와 벡터(DXF)의 차이가 여기서 갈린다. 래스터는 픽셀만 있고 "이 픽셀이 몇 mm인가"라는 정보가 없어서 사람이 알려줘야 한다.

## 설계 판단

### 아키텍처 제약이 기능 후보를 먼저 거른다

DWG를 여는 세 번째 길은 서버 변환이었다. ODA File Converter나 Autodesk Platform Services, CloudConvert 같은 API를 쓰면 확실히 된다. 기술적으로는 제일 쉬운 축에 든다.

그런데 여둘까는 백엔드가 없고, 도움말과 privacy.html에 "모든 작업은 내 브라우저 안에서만 처리되며 서버로 올라가지 않습니다"라고 적혀 있다. 사무실 평면도는 회사 자산이라 이 약속이 이 도구를 쓰는 이유이기도 하다. 서버 변환은 그 문장을 지우는 대가를 요구한다.

그래서 검토가 이렇게 끝났다.

```text
DWG 직접 파싱  → 파서 없음            ❌
LibreDWG WASM → 앱 전체가 GPL        ❌
서버 변환      → 무전송 원칙 위반      ❌
PDF 변환 안내  → 이미 지원되는 경로     ✅
```

세 개가 다른 이유로 떨어졌는데, 공통점은 기술이 아니라 프로젝트가 이미 정해 둔 제약에 걸렸다는 것이다. 제약이 명확하면 후보를 빨리 거를 수 있다.

### 막는 메시지는 다음 행동을 알려줘야 한다

"지원하지 않는 형식입니다"는 사용자를 막다른 곳에 세운다. 총무부서 담당자는 DWG가 왜 안 되는지 알 필요가 없고, 알아도 할 수 있는 게 없다. 필요한 건 지금 뭘 하면 되는지다.

```text
❌ 지원하지 않는 파일 형식입니다.

✅ 캐드 파일(.dwg/.dxf)은 직접 열 수 없습니다.

   무료 캐드 뷰어(DWG TrueView, 오토데스크 뷰어 등)로 도면을 연 뒤
   PDF로 인쇄·내보내고, 그 PDF를 올려주세요.
```

도구 이름을 구체적으로 적은 것도 의도한 것이다. "캐드 뷰어로 변환하세요"라고만 하면 뭘 깔아야 하는지 찾는 게 또 일이 된다.

그리고 이 안내를 두 군데에 뒀다. 하나는 실제로 파일을 골랐을 때(막는 자리), 하나는 도움말 「시작하기」(올려보기 전에 아는 자리). 앞의 것만 있으면 시도해봐야 알게 된다.

### 안 한 결정도 기록 대상이다

무엇을 만들었는지는 코드에 남는다. 무엇을 안 만들기로 했는지는 아무 데도 안 남는다. 몇 달 뒤에 "DWG 지원하면 좋겠는데?" 하고 똑같은 조사를 처음부터 다시 하게 된다.

그래서 CLAUDE.md에 결론이 아니라 근거를 적었다.

```markdown
캐드 파일(.dwg/.dxf)은 지원하지 않는다 — DWG는 비공개 바이너리라 브라우저
파서가 없고, WASM 포팅(LibreDWG)은 GPL-3.0이라 못 쓰며, 서버 변환은
"도면을 서버로 안 보낸다"는 원칙과 충돌한다. (…) DXF는 텍스트 포맷이라 MIT
라이브러리로 지원 가능하고 도면 단위가 있어 축척 자동 인식까지 되지만,
현재는 구현 안 함.
```

"안 함"만 적으면 다시 물어보게 되고, "왜 안 함"까지 적으면 조사가 끝난다. 조건이 바뀌었을 때(예: DWG 규격이 열리거나 MIT 파서가 나오면) 다시 열어볼 근거도 같이 남는다.

## 요약

- `accept` 속성은 필터일 뿐이라 코드 가드가 따로 필요하고, 그 가드는 읽기 전에 와야 한다
- `file.type`은 비어 올 수 있으니 확장자와 함께 보고, `input.value`를 비워야 재선택이 된다
- `FileReader`는 내용을 판단하지 않는다. 실패가 예외로 안 올라오는 경로를 먼저 의심할 것
- 라이브러리는 "되는가" 다음에 "무슨 라이선스인가"를 본다. GPL은 정적 웹앱 전체를 물들인다
- 프로젝트가 이미 정해 둔 제약(무전송·빌드 없음)이 기능 후보를 가장 빨리 걸러준다
- 막는 메시지에는 다음 행동을 넣고, 안 하기로 한 결정은 근거까지 문서에 남긴다
