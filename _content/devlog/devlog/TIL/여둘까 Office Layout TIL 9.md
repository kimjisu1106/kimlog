빈 곳을 끌어 여럿을 고르는 기능과 여러 파일을 한 PDF로 묶는 변환을 만들었다. 만드는 것보다 "간헐적으로 안 되는" 것을 잡는 데 더 오래 걸렸고, 원인은 전부 캔버스 밖에 있었다.

---

## 끌어서 고르기

### 방향으로 판정을 가르는 것이 캐드의 관례다

선택 상자에 걸린 것을 고르는 방법은 두 가지다. 상자 안에 완전히 들어온 것만 고르거나(window), 조금이라도 겹치면 고르거나(crossing). 캐드는 이걸 드래그 방향으로 가른다.

```js
const crossing = end.x < start.x;   // 오른쪽 → 왼쪽이면 걸친 것까지
```

왼쪽에서 오른쪽은 완전 포함, 오른쪽에서 왼쪽은 교차다. 이걸 따르면 도면을 쓰던 사람에게는 설명이 필요 없다. 대신 지금 어느 쪽인지 보이게 해야 해서, 파란 실선과 초록 점선으로 갈랐다.

판정 자체는 사각형 두 개의 관계다.

```js
const inside  = b.x >= r.x && b.y >= r.y &&
                b.x + b.width <= r.x + r.width && b.y + b.height <= r.y + r.height;
const overlap = !(b.x > r.x + r.width || b.x + b.width < r.x ||
                  b.y > r.y + r.height || b.y + b.height < r.y);
```

교차 판정은 "겹친다"를 직접 쓰지 않고 "안 겹치는 네 경우"를 뒤집는 편이 짧고 실수가 적다.

---

### 회전한 도형은 외곽 상자로 비교한다

도형이 45도로 돌아가 있으면 실제 모양과 외곽 상자가 다르다. 엄밀하게 하려면 회전 사각형끼리 교차를 따져야 하지만, 선택은 사람이 눈대중으로 끄는 동작이라 외곽 상자로 충분하다.

```js
const b = n.getClientRect({ relativeTo: mainLayer });
```

`relativeTo`를 좌표공간의 기준 레이어로 주는 게 중요하다. 화면 기준으로 받으면 확대·이동한 만큼 어긋나서, 상자와 도형이 다른 좌표계에서 비교된다.

---

### 좌드래그를 쓰려면 먼저 좌드래그를 회수해야 한다

캔버스 라이브러리가 이미 좌드래그로 화면 이동을 하고 있었다. 새 기능을 얹기 전에 그걸 꺼야 한다.

```js
stage.draggable(false);   // 좌드래그는 이제 범위 선택이 쓴다
```

대신 화면 이동은 휠클릭·우클릭·Space와 함께 끄는 세 방법으로 남겼다. 입력 하나에 동작 둘을 태울 수는 없으니, 새 동작을 넣을 때는 그 입력이 지금 무엇을 하고 있는지부터 확인해야 한다.

---

## 상태가 걸리는 자리는 대개 창 밖에 있다

### 캔버스 밖에서 버튼을 떼면 끝났다는 신호가 안 온다

선택 상자를 끌다가 캔버스 경계를 넘어가 버튼을 떼면, 캔버스에 붙인 마우스업은 오지 않는다. 시작만 하고 끝나지 않은 상태가 남아 상자가 화면에 그대로 있고 다음 동작이 꼬인다.

```js
stage.on("mouseup", (e) => finishBand(e.evt.shiftKey));
window.addEventListener("mouseup", (e) => { if (_bandStart) finishBand(e.shiftKey); });
```

시작은 캔버스에서 받되 끝은 창에서도 받는다. 드래그처럼 "시작과 끝이 있는 동작"은 끝을 창 단위로 받아 두는 편이 안전하다.

---

### 창 포커스가 나가면 키를 뗀 신호도 오지 않는다

Space를 누른 채 다른 창으로 넘어갔다 오면, 뗀 신호를 우리 창이 못 받아 계속 눌린 것으로 남는다. 그러면 끌기가 선택이 아니라 화면 이동으로 새고, 사용자는 "어떤 때는 되고 어떤 때는 안 된다"고 느낀다.

```js
window.addEventListener("blur", () => {
  _spaceDown = false; _panning = false; _bandStart = null;
});
```

키를 눌러 무언가를 바꾸는 상태는 `blur`에서 반드시 풀어 준다. 알트탭 한 번으로 앱이 이상해지는 버그의 상당수가 여기서 나온다.

---

### 한 번만 무시하려고 남긴 표시가 안 지워지면 다음 것이 먹힌다

선택을 끝내면 곧바로 클릭 이벤트가 따라온다. 그대로 두면 방금 고른 것이 해제되므로 "다음 클릭 한 번은 무시" 표시를 남기는데, 그 클릭이 안 오는 경우(캔버스 밖에서 뗀 경우)에는 표시가 그대로 남는다. 그리고 한참 뒤의 멀쩡한 클릭 하나를 삼킨다.

```js
stage.on("mousedown", (e) => { if (e.evt.button === 0) _skipClick = false; });
```

"다음 한 번만"류의 표시는 쓰이지 않을 수도 있다고 봐야 한다. 다음 동작이 시작될 때 무조건 지우면 남을 일이 없다.

---

## 파일 다루기

### 사용자 클릭으로 여는 창은 클릭과 창 사이에 무거운 일을 두면 안 된다

"다른 이름으로 저장"이 아무 반응이 없었다. 파일 선택창을 여는 브라우저 기능은 사용자가 방금 조작했다는 자격을 요구하는데, 우리는 저장할 내용을 먼저 만들고 있었다. 암호를 건 프로젝트는 열쇠를 만드는 데 반복 60만 회가 걸려 그 사이 자격이 만료되고, 창은 안 뜬 채 넘어갔다.

```js
// ❌ 무거운 일 → 창
const text = await encryptText(...);
const handle = await showSaveFilePicker(...);

// ✅ 창 → 무거운 일
const handle = await showSaveFilePicker(...);
const text = await encryptText(...);
```

자격이 만료돼 실패하면 예외가 나긴 하지만 사용자에겐 "아무 일도 안 일어남"으로 보인다. 순서를 바꾸는 것이 근본 해결이다.

---

### 여러 파일을 순서대로 처리하려면 여는 함수가 기다릴 수 있어야 한다

파일을 하나씩 열어 화면을 그림으로 뜨려는데, 배경 그림은 로딩이 끝나야 그려진다. 여는 함수가 그걸 알려주지 않으면 아직 빈 화면을 뜨게 된다.

```js
function loadData(d, quiet) {
  return new Promise((resolve) => {
    const finish = () => { /* ... */ resolve(); };
    if (d.bg) { img.onload = () => { /* ... */ finish(); }; img.src = d.bg; }
    else finish();
  });
}
```

콜백으로 끝나던 함수를 약속(Promise)으로 감싸면 `for` 문에서 `await` 한 줄로 줄세울 수 있다. 반복 처리를 붙일 때 가장 먼저 확인할 것은 "이 함수가 언제 끝났다고 알려주는가"다.

---

### 파일을 여러 개 내려받는 대신 한 파일로 묶는다

파일마다 PDF를 하나씩 저장하면 브라우저가 "여러 파일 다운로드를 허용하시겠습니까"를 묻거나 아예 막는다. 한 PDF에 쪽을 쌓으면 그 문제가 없고 인쇄·공유도 편하다.

```js
if (!pdf) pdf = new jsPDF({ orientation, unit: "px", format: [worldW, worldH] });
else pdf.addPage([worldW, worldH], orientation);
```

쪽마다 크기와 방향을 따로 줄 수 있어서, 도면 크기가 제각각이어도 한 파일에 담긴다.

---

### 일괄 처리는 시작 전 상태를 떠 두고 끝나면 되돌린다

파일을 하나씩 실제로 열어 처리하는 방식이라, 끝나면 사용자가 하던 작업이 사라진다. 저장 기능이 이미 "현재 상태를 데이터로 뜨는 일"을 하고 있으니 그걸 그대로 쓴다.

```js
const backup = buildData(projectName);
// ... 파일들 처리 ...
await loadData(backup, true);
```

저장·불러오기가 같은 모델을 쓰고 있으면 이런 임시 보관이 공짜로 따라온다. 되돌릴 때 확인창이 뜨지 않도록 조용한 모드를 하나 두는 것도 잊지 말아야 한다.

---

### 모달 안에서 이벤트를 끊으면 바깥이 하던 뒷정리도 같이 끊긴다

창 전체에 파일을 끌면 테두리 표시가 뜨고, 떨어뜨리면 창 핸들러가 그 표시를 끈다. 그런데 변환 모달의 드롭 영역이 이벤트를 자기 선에서 끊자 표시가 남았다.

```js
zone.addEventListener("drop", (e) => {
  e.preventDefault(); e.stopPropagation();
  clearFileDrag();   // 바깥이 못 하니 여기서 직접
});
```

`stopPropagation`은 "이 코드가 처리했다"는 뜻이지 "바깥이 하던 일이 필요 없다"는 뜻이 아니다. 끊는 순간 바깥의 뒷정리까지 코드 책임이 된다.

---

### 캡처에 담겨야 하는 것은 화면이 아니라 좌표공간에 그린다

도면 왼쪽 위에 프로젝트 이름을 넣었다. 화면 좌상단에 고정하면 보기엔 같지만 내보내기에는 안 담긴다 — 내보내기가 화면이 아니라 도면 영역을 캡처하기 때문이다.

그래서 도면 안쪽 좌표에 그리고, 여백은 도면 크기에 비례시켰다. 글자 크기도 화면 픽셀이 아니라 실측 단위로 두면 축척을 다시 잡을 때 함께 따라간다.

"어디에 그리는가"는 보이는 위치가 아니라 그 그림이 무엇의 일부인지로 정한다.
