"PPT를 얼마나 뽑았나"를 세고 싶었다. 그런데 세어 보니 그동안의 횟수는 아예 남아 있지 않았다. 왜 그런지, 그리고 앞으로 세려면 뭘 해야 하는지.

---

## 브라우저가 바로 받는 다운로드는 서버가 모른다

이 앱은 PPT를 서버에서 만들지 않고 브라우저에서 만들어 그 자리에서 다운로드한다. 파일이 서버를 거치지 않으니, 서버 입장에선 누가 언제 몇 번 뽑았는지 알 방법이 없다. 로그인·곡 등록 같은 건 서버를 거치니 저절로 기록에 남지만, 내보내기는 그 흐름 밖이라 지나간 횟수는 복구할 수도 없다.

앞으로 세려면, 세고 싶은 그 순간에 서버로 한 번 알려 주는 수밖에 없다. '내보내기'를 누를 때 작은 요청을 서버로 보내 기록만 남기게 했다.

```ts
// 내보내기 성공 시 기록만 남긴다. 보내되 결과는 신경 안 쓰고 던져 두기(fire-and-forget)
export function logContiExport(setlistId: number): void {
  fetch(`/api/setlists/${setlistId}/log-export`, { method: "POST" }).catch(() => {});
}
```

서버는 이 요청을 받아 기존 활동 로그 테이블에 `export_pptx` 한 줄을 남긴다. 그러면 로그인·요청 집계와 똑같이 "기간별 몇 번, 어떤 콘티를, 누가, 언제"를 뽑을 수 있다.

한계도 분명히 해 뒀다. 이건 "다운로드 버튼을 눌렀다"는 기록이지, "파일이 실제로 잘 받아졌다"는 보장은 아니다. 브라우저 밖의 다운로드 성공까지는 웹이 못 잡는다. 세려는 게 "내보내기 시도 횟수"라 이걸로 충분했다 — 무엇을 세는지 먼저 정하면 어디에 기록을 심을지가 정해진다.

---

## 이모지 버튼을 옆 글자 버튼과 같은 크기로

곡 메모 버튼(💬)을 옆의 삭제 버튼(✕)과 나란히 뒀더니 크기가 어긋났다. 같은 버튼 스타일을 줬는데도 그랬다. 이모지와 글자는 차지하는 폭이 다르기 때문이다 — 같은 글자 크기여도 이모지가 더 넓다.

여백(padding)만 맞춰선 폭이 안 맞는다. 그래서 두 버튼을 내용과 무관하게 같은 크기가 되도록, 고정 정사각으로 잡고 가운데 정렬했다.

```css
.conti-icon-btn {
  width: 30px;
  height: 30px;
  padding: 0;
  display: inline-flex;
  align-items: center;
  justify-content: center;
}
```

내용(이모지든 글자든)이 폭을 정하게 두면 나란한 버튼이 안 맞는다. 크기를 내용이 아니라 상자가 정하게 하면 무엇을 넣든 똑같아진다.

---

## 요약

- 브라우저에서 바로 받는 다운로드는 서버 기록에 안 남는다. 세려면 그 순간(클릭 시) 서버로 한 줄 남긴다. 무엇을 셀지(시도냐 성공이냐)를 먼저 정한다.
- 이모지와 글자는 폭이 다르다. 나란한 아이콘 버튼은 내용이 아니라 상자(고정 크기 + 가운데정렬)가 크기를 정하게 한다.
