## 출시 전에 확인하는 것

### 개발용 기능은 주석이 아니라 코드로 막는다

숨은 조작으로 재화(하트·코인)를 한 번에 채우는 기능이 있었다. 개발 중에 쓰려고 만든 것이다.

이게 출시용 빌드에도 그대로 들어가 있었다. 코드에는 이렇게만 적혀 있었다.

```dart
onLongPress: _debugRefill, // DEBUG: 배포 전 제거
```

주석은 실행되지 않는다.

나머지 개발용 기능(설정의 디버그 항목, 지나간 레벨 재플레이, 튜토리얼 강제 재생, 테스트 광고 ID)은 전부 빌드 모드로 막혀 있어서 출시본에서 자동으로 빠진다. 그래서 "디버그는 다 처리됐다"고 보였고, 이것만 주석에 의존하는 걸 못 봤다.

```dart
// 다른 것들과 같은 방식으로
onLongPress: kDebugMode ? _debugRefill : null,
```

- 빌드 모드로 막으면 출시본에서 코드 자체가 빠진다. 지우는 것과 효과가 같으면서 개발 중에는 계속 쓸 수 있다
- 확인은 출시용 빌드를 실기기에 깔아 직접 눌러 본다. 개발용 빌드에서는 어차피 다 동작하므로 확인이 되지 않는다
- 재화를 주는 기능이 뚫려 있으면 경제 설계가 통째로 무의미해진다. 광고 보고 코인 받기도, 코인으로 하트 사기도 의미가 없어진다

### 아이콘은 안쪽 안전영역 안에 그린다

홈 화면 아이콘에서 그림이 꽉 차 보이고 가장자리가 잘렸다.

안드로이드 아이콘은 바깥쪽을 마스크로 깎고, 런처에 따라 확대까지 한다. 그래서 그림이 안쪽 안전영역(가운데 약 66%) 안에 들어가야 한다. 우리 그림은 폭의 94%를 채우고 있었다.

전에 스토어용 아이콘에 여백을 넣으면서 "런처 아이콘은 OS가 안전영역을 잡아 주니 그대로 둬도 된다"고 적었는데 틀렸다. OS가 잡아 주는 건 마스크 모양이지, 그림이 넘으면 그대로 잘린다.

- 스토어용과 런처용은 규격이 다르다. 둘 다 여백이 필요하지만 이유가 다르다
- 넉넉하게 60% 정도로 두면 어느 런처에서도 안 잘린다

### 처음 정하면 못 바꾸는 값이 있다

앱 식별자를 로그스톤 도메인 기준으로 바꾸려 했다. 코드는 세 군데뿐이라 금방이었는데, 확인해 보니 딸려오는 게 있었다.

- 분석 도구 설정 파일에 식별자가 박혀 있다. 새로 등록하고 파일을 다시 받아야 한다
- 광고 쪽도 콘솔에서 고쳐야 한다. 안 고쳐도 개발 중에는 테스트 광고가 계속 나와서 눈치채기 어렵다

그리고 스토어에 한 번 올리면 영원히 못 바꾼다. 바꾸려면 새 앱으로 등록해야 하고 설치·리뷰·평점이 전부 사라진다.

- 이런 값은 프로젝트를 처음 만들 때 정한다. 도구에 따라 시작 명령에 옵션으로 줄 수 있다
- 외부 서비스를 붙이기 전이 마지막 기회다. 붙이고 나면 콘솔 작업이 따라온다

## 같은 값을 여러 곳에서 다시 만들면

### 그중 하나는 빠진다

출시한 뒤에도 레벨을 추가할 수 있게, 기존 레벨은 다시 만들지 않는 모드를 넣었다. 기존 레벨이 쓰던 그림을 "사용 중" 목록에 넣고 시작하면 중복이 안 나올 것으로 봤다.

그런데 중복이 났다. 1번과 501번이 같은 그림이었다.

목록을 처음에 채워 뒀는데, 뒤쪽 두 곳이 그 목록을 그때그때 다시 만들고 있었다.

```python
used = {v[2] for v in best.values()}   # 이번에 만든 것만 들어간다
```

동결 상태에서는 이번에 만든 것이 두 개뿐이라, 기존 500개가 쓰던 그림이 전부 미사용으로 보였다.

- 같은 의미의 값을 여러 곳에서 다시 계산하면, 그중 하나는 조건이 빠진다. 이번 주에만 같은 종류를 여러 번 만났다
- 다시 만드는 자리를 전부 찾는 것보다, 한 곳에서 관리하고 갱신만 하는 편이 낫다
- 검증은 파일 해시로 했다. 502까지 늘려도 1~500 파일이 바이트 단위로 그대로인지 본다 — "안 바뀌었다"는 눈으로 확인할 수 없다

## 스토어에 적는 글

### 규칙을 다시 읽고 쓴다

설명 문구 초안에 사실이 틀린 문장이 둘 있었다.

"색이 섞인다", "엉뚱한 자리에 색이 굳는다"고 썼는데, 이 게임에서 모래는 자기 색 자리에만 들어간다. 섞이지도 않고 엉뚱한 데 굳지도 않는다. 실제 실패는 더 부을 수 있는 수가 없어지는 것이다.

만들면서 규칙을 다 아는 것 같아도, 글로 옮길 때는 인상으로 쓰게 된다.

- 스토어 문구는 규칙 문서를 다시 읽고 쓴다. 틀린 설명은 리뷰로 돌아온다
- 특히 "이렇게 하면 실패한다"는 문장은 실제 실패 조건을 확인하고 쓴다

### 조건부로만 되는 기능은 조건을 적거나 빼거나

"오프라인으로 플레이할 수 있다"고 적었다가 뺐다.

게임 자체는 연결 없이 된다. 그런데 광고를 보고 받는 보상은 연결이 필요하다. 크게 적어 두면 "오프라인이라더니 왜 안 되냐"가 된다.

- 단서를 달아 적거나(괄호로), 아예 빼거나 둘 중 하나다. 조건을 숨기고 크게 적는 선택지는 없다
- 왜 뺐는지 메모로 남겼다. 안 그러면 나중에 "오프라인 되는데 왜 안 적었지" 하고 다시 넣게 된다
