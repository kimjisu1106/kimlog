## 측정으로 품질을 정할 때

### 지표가 재는 것과 재고 싶은 것은 다를 수 있다

이 게임은 판의 난이도를 봇으로 잰다. 봇은 한 수마다 정해진 확률로 실수하고, 여러 번 돌려 성공 비율을 낸다. 그 비율이 목표 구간에 들면 좋은 판으로 본다.

그런데 최고 난이도로 만든 판이 벽 0개, 놓을 자리 15칸으로 나왔다. 수치는 목표 안이었다.

이유가 분명했다. 봇은 볼 게 없어도 운이 나쁘면 실패한다. 반대로 사람은 볼 게 없으면 그냥 푼다. 지표가 재고 있던 것은 "무작위로 두면 얼마나 실패하나"였지 "얼마나 생각해야 하나"가 아니었다.

지표를 더 정교하게 만드는 대신 지표가 못 보는 것을 따로 못 박았다.

```python
WALL_FLOOR = {"hard": 3, "veryhard": 5, "extreme": 7}
TIER_MIN_BASKETS = {"hard": 20, "veryhard": 24, "extreme": 28}
```

수치가 아무리 좋아도 이 아래로는 안 내려간다. 지표로 잡히지 않는 품질은 구조로 막는 편이 확실하다.

---

### 기준을 바꾸는 것과 목표를 바꾸는 것은 파급이 다르다

난이도를 올리는 손잡이가 여럿이었다.

| 손잡이 | 성격 |
| --- | --- |
| 목표 곡선 낮추기 | 목표 숫자를 바꾼다 |
| 관문 주기 촘촘히 | 목표가 낮은 판을 늘린다 |
| 측정 봇을 더 잘하게 | 목표 숫자의 의미를 바꾼다 |

앞의 둘은 "0.30을 맞춰라"에서 "0.26을 맞춰라"로 바꾸는 것이다. 세 번째는 다르다. 봇이 잘해지면 같은 판의 측정값이 올라가므로, 같은 0.26을 맞추려고 더 어려운 배치를 찾게 된다. 숫자는 그대로인데 그 숫자가 뜻하는 난이도가 통째로 올라간다.

- 파급이 큰 만큼 한 번에 여럿 바꾸면 무엇이 효과를 냈는지 모른다. 곡선부터 바꿔 보고, 부족할 때 기준을 건드리는 순서가 맞다

## 규칙이 안 닿는 곳

### 예외 경로는 규칙의 사각지대다

상위 난이도에 벽 최소 개수를 넣었는데 결과가 그대로였다. 코드는 분명히 들어가 있었다.

원인은 자리였다. 정상 경로는 벽 개수를 조절해 가며 목표를 맞추는데, 여기에 하한을 걸었다. 그런데 정상 경로가 다 실패하면 떨어지는 안전망이 따로 있었고, 거기서는 벽을 아예 안 깔았다.

```python
# 정상 경로 — 하한을 걸어 둔 곳
wall_budget = max(wall_floor, wall_budget - 1)

# 안전망 — 여기까지 안 닿았다
d = build(..., walls=set(), ...)
```

문제가 된 판들은 전부 안전망을 탄 판이었다. 어려운 그림이라 정상 경로가 실패한 것이니, 하필 규칙이 가장 필요한 판이 규칙을 안 거쳤다.

- 규칙을 넣을 때는 그 값이 정해지는 자리를 전부 찾는다. 하나만 고치면 나머지가 그대로다
- 예외 처리 자리를 특히 본다. "정상적이지 않은 경우"라 검사를 건너뛰게 짜기 쉽다

---

### 하한이 생성 실패로 이어지면 더 나쁘다

안전망에도 하한을 걸었더니 몇몇 판이 아예 안 만들어졌다. 이 생성기는 못 만든 판의 그림을 버리고 다른 그림으로 넘어가므로, 헐거운 판 하나보다 손해가 크다.

하한 우선, 실패하면 완화하는 2단으로 뒀다.

```python
for per in sizes:                  # 1차 — 하한을 만족하는 배치만
    if count(per) < floor and not relaxed:
        skipped = True
        continue
    ...
if best is None and skipped:       # 다 실패했으면 2차 — 하한 없이
    relaxed = True
    ...
```

품질 하한은 "지키면 좋은 것"이지 "못 지키면 포기할 것"이 아니다. 어느 쪽인지 정하고 넣어야 한다.

## 원인을 찾을 때

### 같은 결과가 나오면 코드가 같은지부터 본다

하한을 넣고 다시 돌렸는데 위반 개수가 직전과 완전히 같았다. 이걸 "결과 파일이 섞였다"고 읽었다. 마침 재생성이 도는 중에 새로 시작한 적이 있어 그럴듯했다.

파일을 다 지우고 다시 돌렸는데 또 같았다. 그제야 알았다 — 이 생성기는 무작위 씨앗이 레벨 번호로 고정되어 있어서, 같은 코드면 몇 번을 돌려도 같은 결과가 나온다.

즉 "결과가 같다"는 섞임의 증거가 아니라 수정이 그 경로에 닿지 않았다는 증거였다. 처음부터 그렇게 읽었으면 파일을 지우고 다시 돌리는 15분을 안 썼다.

- 결정적(같은 입력이면 늘 같은 결과가 나오는)인 프로그램에서 같은 입력에 같은 출력은 정상이다. 놀랄 일이 아니라 단서다
- 수정이 반영됐는지는 결과 전체가 아니라 그 수정이 직접 만드는 값 하나로 확인한다

### 평균끼리 비교할 때는 기준이 같은지 본다

후반이 목표보다 크게 쉬운 줄 알았다. 구간 평균과 그 구간 중앙 레벨의 목표를 비교했기 때문이다.

목표는 레벨마다 다르다. 어떤 레벨은 0.15, 바로 옆은 0.45일 수 있다. 한쪽만 대푯값으로 눌러 놓고 비교하니 없는 차이가 보였다.

레벨마다 자기 목표와 비교해 세어 보니 실제로는 400개 중 76개만 벗어났고, 크게 벗어난 것은 6개였다.

- 비교하려는 두 값이 같은 방식으로 만들어졌는지부터 확인한다
- "평균이 이렇다"는 결론 전에 분포를 본다. 몇 개가 크게 튀는 것과 전체가 밀린 것은 대처가 다르다
