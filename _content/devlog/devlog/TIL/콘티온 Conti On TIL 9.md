곡 데이터에 분류·속성·중복 감지·유형 제약을 붙이는 하루였다. 그 과정에서 배운 것들을 모았다.

---

## 번호로 정해지는 분류는 저장하지 말고 계산하게

곡마다 번호가 있고, 번호 구간마다 분류가 정해져 있다. 이 분류를 컬럼에 따로 저장하면 번호가 바뀔 때마다 같이 고쳐야 하고, 처음 채울 때도 전체를 한 번 훑어야 한다. 그런데 번호에서 분류가 100% 계산되니, 저장하는 대신 "번호로 그때그때 계산되는 컬럼"으로 뒀다. 백필(기존 행을 뒤늦게 한 번에 채우기)도 동기화도 필요 없다.

```sql
-- 번호 구간으로 분류가 정해지므로 저장하지 않고 계산되게 둔다(생성 컬럼)
ALTER TABLE songs ADD COLUMN category TEXT GENERATED ALWAYS AS (
  CASE
    WHEN number BETWEEN 1 AND 8 THEN 'A'
    WHEN number BETWEEN 9 AND 55 THEN 'B'
    -- ...
  END
) VIRTUAL;
```

반면 번호로 안 나오고 곡마다 손으로 정해야 하는 속성 플래그는 계산이 안 되니 일반 컬럼 + 백필로 뒀다. 규칙이 있으면 계산, 없으면 저장 — 그 갈림이 컬럼 종류를 정한다.

---

## 같은 규칙을 화면과 서버 두 곳에서 지킨다

곡 속성 플래그 몇 개 중 일부는 다른 걸 함의한다. 하위 속성 A나 B를 켜면 상위 속성 C가 자동으로 켜지고, 그 상태에선 C를 못 끈다. 화면에서만 막으면 코드를 우회해 서버로 값을 직접 보내는 경우 규칙이 깨진다. 그래서 화면(체크박스 잠금)과 서버(저장 직전 보정) 양쪽에서 같은 규칙을 강제했다.

```ts
// 서버: A나 B가 켜져 있으면 C도 켠다(화면이 지키더라도 서버에서 다시 보정)
const c = a || b || cInput ? 1 : 0;
```

불변식(늘 지켜져야 하는 규칙)은 한 곳에서만 지키면 다른 문으로 깨진다.

---

## 화면에 웬 0 — 조건 렌더링의 함정

속성이 하나도 없는 곡을 열었더니 내용 위에 `0`이 찍혀 있었다. 원인은 조건 렌더링이었다.

```jsx
// ❌ 셋 다 0이면 (0 || 0 || 0) = 0, 그리고 0 && <div> 는 화면에 0을 찍는다
{(a || b || c) && <div>...</div>}

// ✅ 불리언으로 바꾸면 false && ... 라 아무것도 안 나온다
{(a === 1 || b === 1 || c === 1) && <div>...</div>}
```

JSX는 `false`·`null`·`undefined`는 안 그리지만 `0`은 숫자라 그린다. 숫자를 조건에 그대로 쓰면 0이 새어 나온다.

## 필터 옵션은 데이터에서 뽑되, 원래 순서로

분류 필터 드롭다운을 코드에 박지 않고 DB에 실제로 있는 분류만 뽑아 채웠다. 나중에 분류가 늘어도 자동으로 반영되게 하려는 것이다. 그런데 그냥 중복 제거로 뽑으면 가나다순이 돼서 원래 목차 순서가 깨진다. 각 분류의 첫 곡 번호로 정렬해 목차 순서를 지켰다.

```sql
SELECT category FROM songs
WHERE category IS NOT NULL
GROUP BY category
ORDER BY MIN(number);  -- 분류가 처음 나오는 번호 순 = 목차 순
```

## 막되, 화면과 서버 두 곳에서 막는다

특정 속성을 가진 곡만 담을 수 있는 콘티 유형을 만들었다. 담기 전에 화면에서 걸러 경고하지만, 그것만으론 저장 요청을 직접 보내면 뚫린다. 그래서 저장할 때 서버가 다시 검사해 위반이면 거부한다.

또 이미 만든 콘티를 그 유형으로 바꿀 때, 안 맞는 곡이 이미 들어 있으면 그 곡 목록을 되돌려줘서 "이것들을 먼저 빼라"고 안내했다. 그냥 "안 됨"보다 무엇을 고쳐야 할지 알려주는 게 낫다.

```ts
// 유형 조건에 안 맞는 곡이 담겨 있으면 그 목록을 돌려준다
const bad = await db
  .prepare(`SELECT s.title FROM items i JOIN songs s ON s.id = i.song_id
            WHERE i.list_id = ? AND s.attr != 1`)
  .bind(id)
  .all();
if (bad.results.length)
  return c.json({ error: "not_allowed", titles: bad.results.map((r) => r.title) }, 400);
```

## 유사도 함수가 없는 DB에서 닮은 항목 찾기

같은 곡이 제목·내용이 조금 달라 따로 등록되는 걸 막고 싶었다. SQLite엔 유사도 함수가 없어 서버(Worker)에서 계산했다. 제목은 공백·문장부호를 지운 키로 만들어 편집거리 유사도를 재고(0.8 이상이면 닮음), 내용은 앞부분만 잘라 비교했다. 전체 곡의 내용을 다 읽으면 부하가 크니, 쿼리에서 앞 80자만 잘라 받아 오갈 데이터를 줄였다.

```ts
// 공백·문장부호 지우고 소문자로 — "가나 다라!" 와 "가나다라" 를 같게 본다
const key = (s) => s.toLowerCase().replace(/[\s\p{P}\p{S}]/gu, "");
```

```sql
SELECT id, title, substr(body, 1, 80) AS head FROM songs WHERE deleted_at IS NULL;
```

막지 않고 "비슷한 게 있다, 그래도 등록?"으로 물었다. 진짜 다른 곡일 수도 있으니 판단은 사람이 한다.

## 형식을 넓히니 계획했던 기능이 공짜로 따라왔다

콘티에서 곡의 절을 골라 순서를 정하는 "배치"는 절 번호의 배열로 저장돼 있었다. 여기에 "절 사이에 안내 문구 삽입"을 넣으려고, 배열 항목을 번호 또는 텍스트로 넓혔다.

```ts
type ArrangeItem = number | { t: string }; // 절 번호 또는 삽입 텍스트
```

그런데 이렇게 하고 나니, 따로 만들려던 "그 콘티에서만 곡 내용 고치기"가 저절로 됐다. 원래 절을 빼고 그 자리에 고친 내용을 텍스트로 넣으면 그 콘티에서만 바뀐다. 별도 컬럼·별도 화면을 계획했는데, 형식 하나를 일반화하니 그게 필요 없어졌다. 기능을 더하기 전에 "지금 형식을 조금 넓히면 되나"를 먼저 보면 덜 만든다.

## 수백 개를 스크립트로 만들되, 다시 돌려도 안 겹치게

수백 곡을 손으로 넣을 수 없어, 데이터를 스크립트로 만들어 마이그레이션 SQL을 뽑았다. 두 번 실행돼도 중복이 안 생기게, 이미 있으면 건너뛰는 삽입으로 짰다.

```sql
INSERT INTO songs (number, title)
SELECT 3, '...' WHERE NOT EXISTS (SELECT 1 FROM songs WHERE number = 3 AND category = '...');
```

검증하다 숫자가 안 맞아 당황했는데, 로컬 DB는 원격(운영)과 별개인 개발용 샌드박스라 원래 있던 데이터가 달랐던 것이다. 로컬에서 "몇 개 들어갔나"가 원격과 다른 게 정상이다. 로컬로 문법·로직을 확인하고, 실제 반영·검증은 원격에서 따로 한다.

## 여러 줄 입력은 prompt로 안 된다

"텍스트 삽입"을 처음엔 브라우저 기본 입력창(prompt)으로 받았는데, prompt는 한 줄만 받는다. 여러 줄을 붙여넣으려면 화면 안에 작은 여러 줄 입력칸(textarea)을 둬야 했다. 붙여넣은 걸 줄바꿈으로 잘라 각 줄을 항목 하나로 넣었다.

```ts
textInput
  .split(/\r?\n/)
  .map((l) => l.trim())
  .filter(Boolean)
  .map((t) => ({ t }));
```

---

## 나란한 메뉴 항목이 줄바꿈될 때

메뉴에 항목을 하나 더 넣었더니 글자가 길어 두 줄로 접혔다. 메뉴 폭이 최소값으로 고정돼 있어서였다. 항목이 글자 길이에 맞춰 한 줄로 늘어나게 했다.

```css
.menu-item {
  white-space: nowrap;
}
```

폭을 글자가 정하게 두면, 최소폭보다 넓어져야 할 때 저절로 늘어난다.

## 요약

- 규칙으로 계산되는 값은 생성 컬럼으로(백필·동기화 없음), 곡마다 지정하는 값은 일반 컬럼 + 백필로.
- 불변식은 화면과 서버 두 곳에서 지킨다. 한 곳만 막으면 다른 문으로 깨진다.
- JSX에서 `0 && <div>`는 0을 그린다. 조건은 불리언으로 바꾼다.
- 드롭다운 옵션은 데이터에서 뽑되 원래 순서(첫 항목 번호)로.
- 제약은 화면 경고 + 서버 재검증. 막을 땐 무엇을 고쳐야 할지 목록으로 알려준다.
- 유사도 함수 없는 DB는 서버에서 키 정규화 + 편집거리로, 앞부분만 잘라 부하를 줄인다.
- 기능을 더하기 전에 형식을 넓히면 되는지 본다. 하나를 일반화하면 여러 기능이 흡수된다.
- 대량 삽입은 멱등하게(여러 번 돌려도 결과가 같게, NOT EXISTS). 로컬 DB는 원격과 다른 샌드박스다.
- 여러 줄은 prompt 말고 textarea로. 나란한 항목의 줄바꿈은 nowrap으로 푼다.
