## 오늘 한 일

- 비밀번호 재설정을 메일 발송 없이 만들었다. 무료로 쓸 수 있는 방법 중에서 운영자가 1회용 링크를 만들어 전달하는 방식을 골랐다.
	- 회원이 지원 메일로 알려 오면, 관리자 계정 화면에서 링크를 만들어 복사해 보낸다.
	- 링크는 24시간 동안 한 번만 쓸 수 있다. 비밀번호가 바뀌면 같은 링크는 더는 안 통한다.
	- 앱 로그인 화면의 「비밀번호를 잊으셨나요?」는 자동 발송이 없다는 걸 숨기지 않고 지원 메일로 안내한다.
- 우리 쪽 장애로 못 들은 기간은 이용 기간을 늘려 주는 방식으로 보상하기로 하고 백로그에 넣었다.
- 코드 정리 점검 목록 열한 가지를 전부 하기로 했다.
	- 깨진 테스트를 다시 썼고, 앱으로 옮긴 뒤 멈춰 있던 옛 웹 화면 코드를 지웠다.
	- 네 군데 중복된 코드(재생목록 이름 입력 창, 상태 표시 등)를 하나로 묶었다.
	- 개편에서 빠져 있던 관리자 화면을 새 황동색 테마로 맞췄다.
	- 1,000줄이 넘던 스케줄 화면과 홈·재생 화면을 역할대로 쪼갰다.
	- 재생목록 상세 응답에서 화면이 안 쓰는 긴 필드를 뺐다.
- 곡 제목을 한국어·영어 두 칸으로 나누고, 파일명이 그대로 제목이던 770곡에 한국어·영어 제목을 새로 지었다.
	- 같은 곡의 두 제목은 같은 장면을 가리키게 했다(「늦은 카운터」 ↔ 「Late Counter」).
	- 제목에 쓴 「은밀한」이 마음에 들지 않아 「그윽한」·「Amber」로 바꿨다.
- 플레이에 올릴 업로드 키를 만들고, 릴리스 빌드가 그 키로 서명되는 것까지 확인했다.
- 앱 아이콘과 스토어 이미지를 Design에 맡겼다.
	- 아이콘은 시안 네 개 중 R 모노그램을 골라 앱에 넣었다.
	- 그래픽 이미지와 Creem 상품 이미지가 처음엔 별로라서 명판 방향으로 다시 잡았다. 「룸톤」은 크게, 「ROOMTONE」은 작게 했다.
	- 이미지에 가격은 넣지 않고, 한국어·영어 두 벌로 만들었다.
- 스토어 스크린샷에 실제 앱 화면을 넣었다. 운영 테스트 계정에 스케줄 네 개와 재생목록을 만들어 두고 폰에서 찍었다.
- 영어판 스크린샷을 찍으려다 보니 앱 문구가 전부 한국어로 고정돼 있었다. 그래서 앱 자체가 영어를 지원하게 했다.
	- 기기 언어가 한국어가 아니면 손님이 보는 화면을 영어로 보여 준다. 운영자만 보는 관리 화면은 한국어로 둔다.
	- 서버 오류 문구, 기본 재생목록 7개와 태그 37개에도 영어 이름을 붙였다.
	- 사용자가 직접 지은 이름(계정 이름, 내 재생목록)은 번역하지 않는다. 캡처용 계정의 이름만 영어로 바꿔 찍었고, 한국어판에도 그대로 둬도 괜찮다고 정했다.
- 태블릿을 연결해 넓은 화면도 찍었다.
	- 태블릿에서는 사이드 메뉴 위와 페이지 제목에 「룸톤」이 두 번 보였다. 사이드 메뉴 쪽을 R 아이콘으로 바꾸자고 해서 바꿨다.
	- 휴대폰과 태블릿 화면을 한 장에 담은 「휴대폰·태블릿」 이미지를 만들었다.
- Creem과 판매 사이트에 올릴 가로 소개 이미지를 세 방향으로 받아 「한 장에 기능 하나」 방향을 골랐다.
	- 문구가 딱딱해서 부드럽게 해 달라고 했다. 해요체로 바꾸면서 「신탁단체」 같은 어려운 말을 뺐고, 세로 스크린샷도 같은 톤으로 맞췄다.
- 이미지에 쓴 폰트 저작권을 확인했다. 글자는 전부 Noto Sans KR(SIL OFL)이라 상업적으로 써도 된다.
- 앱 폰트를 정했다. 영어는 Archivo, 한글은 Noto Sans KR이다.
	- 폰트를 바꾼 뒤 폰과 태블릿 화면을 다시 찍고, 스토어 이미지 PNG 19장을 새로 뽑아 저장했다.
- 캡처에 쓴 계정은 운영자 테스트 계정으로 계속 쓴다. 구독 기간은 평소엔 비워 두고 전곡 재생을 시험할 때만 넣는다.

## 막힌 부분

- 폰의 미리듣기가 무한 로딩이었다.
	- 원인: 코드 정리에서 파일 전송 부분을 합치다가, 구간 지정(Range 헤더) 없이 파일을 달라는 요청을 처리하지 못하게 됐다. 서버가 500으로 죽었는데, 로컬 시험은 늘 구간을 붙여 보내서 드러나지 않았다.
	- 해결: 구간 없는 요청도 처리하고, 이제 구간이 있을 때와 없을 때를 둘 다 시험한다.
- 운영에 캡처용 데이터를 넣다가 외래 키 오류가 났다.
	- 원인: 넣으려던 계정이 탈퇴 시험으로 지워졌고, 같은 이메일로 다시 가입해 번호가 바뀌어 있었다.
	- 해결: 새 번호로 다시 넣었다.
- 영어로 찍은 스크린샷이 한국어로 나왔다.
	- 원인: 곡 제목만 영어 칸이 있었고, 화면 문구는 코드에 한국어로 고정돼 있었다.
	- 해결: 앱 문구를 한국어·영어 쌍으로 바꿨다(오늘 한 일).
- 새 앱이 폰에 설치되지 않았다.
	- 원인: 폰에 있던 앱은 개발용 키로, 새 앱은 업로드 키로 서명돼 안드로이드가 덮어쓰기를 거부했다.
	- 해결: 한 번 지우고 새로 설치한 뒤 다시 로그인했다. 이후 빌드는 같은 키라 그냥 덮어쓴다.
- 영어 화면인데 둘러보기의 분위기·계절 버튼과 재생 화면의 큰 곡 제목이 한국어로 남았다.
	- 해결: 두 곳도 영어 이름을 쓰게 고쳤다.
- 폰 해상도를 태블릿 크기로 바꿔 넓은 화면을 흉내 내 보았는데, 화면이 가로로 돌지 않아 잘려 나왔다.
	- 해결: 원래대로 되돌리고 실제 태블릿을 연결해 찍었다.
- 새 캡처를 넣으니 영어 「휴대폰·태블릿」 제목이 네 줄로 쪼개졌다.
	- 원인: 영어 문장이 한국어보다 길어 같은 글자 크기로는 한 줄에 안 들어갔다.
	- 해결: 영어판만 글자 크기를 줄여 두 줄로 맞췄다.
- 이미지 스타일에 Noto Sans KR을 못 불러올 때 맑은 고딕으로 바꾸는 설정이 있었다. 맑은 고딕으로 그려졌다면 따져 볼 게 생긴다.
	- 해결: Noto Sans KR만 쓰게 해서 다시 그린 것과 픽셀 단위로 비교했다. 글자 영역이 모두 같아 맑은 고딕은 한 곳에도 쓰이지 않았다.

### 앱에 넣을 한글 폰트가 굵기 하나에 10MB였다

앱이 쓰는 굵기는 400·500·600·700 네 가지다. Noto Sans KR 원본은 굵기당 10MB라, 그대로 넣으면 앱이 40MB 커진다. 굵기를 파일 하나에서 조절하는 가변 폰트는 기기마다 굵기 지정이 다르게 먹을 수 있어 쓰지 않았다.

- 해결: 네 굵기를 고정 파일로 만들면서 한자를 뺐다. 한글 11,172자, 자모, 영문, 기호만 남기니 굵기당 2.8MB가 됐고, 앱은 76MB에서 80MB로 커졌다.
- 남은 한계: 사용자가 이름에 한자를 쓰면 그 글자만 기기 기본 폰트로 나온다. 깨지지는 않는다.
