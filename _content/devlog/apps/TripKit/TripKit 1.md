## 오늘 한 일

- 기존에 만든 것과 유사한 형태의 프로젝트 저장소를 읽고 가져올 것과 버릴 것을 가렸다
	- 가져옴: 빌드·배포 모양, 구글 로그인 흐름, 세션 쿠키
	- 버림: 가입 승인제, 권한 넷, 1시간 유휴 로그아웃
	- 이유: 들어올 수 있는 계정을 둘로 묶으면 승인 절차가 필요 없다. 여행 중 나쁜 망에서 다시 로그인하게 만들면 적던 비용이 날아간다
- 허용 계정 목록을 로그인 때와 매 요청 때 둘 다 검사하게 했다
	- 이유: 링크가 메신저에서 굴러다녀도 남은 못 들어온다. 목록에서 지우면 이미 받은 세션도 바로 막힌다
- GitHub 저장소를 만들고 Cloudflare Pages를 GitHub 연결로 붙였다. D1(데이터베이스)과 구글 로그인 설정까지 마쳐 배포본에서 로그인과 여행 만들기를 확인했다
- 등록하지 않은 구글 계정으로 들어가 보니 구글 단계에서 먼저 막혔다
- 여행 상세 화면과 날짜별 일정을 붙였다
- 준비물 체크리스트를 붙였다. 체크는 화면부터 바꾸고 서버에 보낸다
- 장소 모으기와 지도를 붙였다. 지도는 구글맵으로 정했다
	- 이유: 내년 여행이 해외라서다
	- 일정에 모은 장소를 연결하면 그날 동선을 번호 순서대로 선으로 이어 보여 준다
- 예산·비용을 붙였다. 통화를 섞어 적고 둘 사이 정산까지 하기로 했다
	- 정산은 통화별로 따로 한다. 엔으로 쓴 건 엔으로, 원으로 쓴 건 원으로 주고받는다
	- 혼자 쓴 돈은 개인 지출로 정산에서 뺀다
- 초대 링크를 붙였다. 여행을 만들면 같이 쓰는 사람도 자동으로 넣는 안이 있었는데, 초대받은 사람만 멤버로 두기로 했다
	- 링크는 한 번만 쓸 수 있고 7일이 지나면 만료된다

## 막힌 부분

- 첫 배포가 함수 올리기에서 실패했다
	- 원인: 설정 파일의 데이터베이스 id가 0으로 채운 자리표시값이었다
	- 해결: 원격 D1을 만들고 실제 id를 넣으니 다음 빌드가 통과했다
- Claude가 알려 준 로그인 리디렉트 주소가 실제 배포 주소와 달랐다
	- 원인: Pages가 붙인 기본 주소에 꼬리가 달려 있었고, 커스텀 도메인도 따로 붙어 있었다
	- 해결: 들어갈 수 있는 주소마다 하나씩 등록했다. 코드가 접속한 주소를 그대로 리디렉트 주소로 쓰기 때문이다
- DB 구조를 바꾸는 마이그레이션과 비밀값 등록은 운영 환경을 건드리는 일이라 Claude 쪽에서 실행되지 않았다
	- 해결: 터미널에서 한 줄씩 직접 돌렸다. Pages 빌드는 마이그레이션을 돌리지 않으니 DB 구조가 바뀌는 커밋은 마이그레이션을 먼저 돌린 뒤에 올린다

### 장소 주소를 저장할 수 없다

계획 문서에는 오프라인에서 지도 대신 장소 목록·주소·좌표를 보여 준다고 적혀 있었다. 그러려면 구글 장소 검색으로 고른 장소의 정보를 우리 쪽에 저장해야 하는데, 구글 약관이 그걸 막는다. 무기한 저장해도 되는 것은 장소 id뿐이고, 좌표는 30일까지만 들고 있을 수 있다.

- 해결: 장소 id와 우리 쪽 이름(고칠 수 있다), 좌표만 저장한다. 좌표는 받은 날짜를 같이 적어 두고 30일이 다가오면 여행을 열 때 다시 받는다. 주소는 「구글맵에서 열기」 링크로 대신한다
- 남은 한계: 나중에 오프라인 보기를 붙이면 장소는 이름과 링크만 보인다. 계획에서 주소가 빠진다
