## 오늘 한 일

- 태블릿에서 직접 써 보고 막힌 것을 고쳤다
	- 축척 보정에서 두 번째 점을 찍으면 그 점과 선을 먼저 보여 주고 나서 거리를 묻는다
	- 팔레트를 탭해 가구를 놓으면 서랍이 닫힌다
	- 도형을 손가락으로 짚으면 속성 서랍이 열린다. ▤ 버튼은 없앴다
	- 서랍 손잡이를 툴바에서 빼 도면 좌우 가장자리 위쪽에 꺽쇠(`›` `‹`)로 붙였다
	- 손가락으로 쓰는 기기는 가로·세로와 상관없이 같은 서랍 방식으로 간다
	- 앞서 넣은 크기 표시를 배포본에서 켜 봤다. 글자 크기와 자리는 그대로 두기로 했다
- 손가락으로 점 찍기를 새로 만들었다
	- 누른 채 상하좌우로 끌어 맞추고, 떼는 순간 손가락 자리에 점 하나가 찍힌다
	- 누르는 동안 좌상단에 손가락 밑을 2.5배로 보여 주는 확대 화면(260px)이 뜬다. 손가락이 좌상단으로 가면 우상단으로 비킨다
	- 거리 재기·면적 재기·축척 보정에 똑같이 쓴다
- 도면 위에서 아래로 끌어도 브라우저가 새로고침하지 않게 했다
- 두 손가락으로 확대하고 손을 떼면 점이 하나 찍히던 것을 고쳤다
- 태블릿에 무선 디버깅으로 붙어 배포본을 실제 기기에서 재고 찍는 길을 열었다
- 회귀 검사에 넷을 넣었다 — 탭 배치와 짚기, 손가락 찍기, 두 손가락 확대, Shift+탭 한 번 처리

## 막힌 부분

- 축척 보정에서 두 번째 점이 어디 찍혔는지 보이지 않았다
	- 원인: 점을 그린 직후 거리 묻는 창을 띄우면 브라우저가 그리기를 멈춘다. 점이 화면에 나오기 전에 창이 먼저 떴다
	- 해결: 그려 놓고 한 박자 뒤에 묻는다
- 서랍 손잡이를 화면 좌우 세로 가운데에 붙였더니, 태블릿을 세로로 들었을 때 정확히 전면 카메라 자리였다
	- 해결: 도면 위쪽 모서리로 올렸다. 크롬으로 화면 크기만 흉내 내서는 보이지 않는 자리다
- 태블릿을 가로로 돌리면 서랍이 아예 사라지고 양옆 패널이 고정됐다
	- 원인: 가로가 1691px이라 폭만 보면 데스크톱으로 잡혔다. 게다가 이 태블릿은 S펜 때문에 「마우스를 올려 볼 수 있는 기기」로 스스로를 알린다
	- 해결: 폭이 아니라 손가락으로 쓰는 기기인지로 가른다
- 도형을 짚어도 속성 서랍이 열리지 않았다
	- 원인: 도형 쪽 처리가 그 탭을 받고 거기서 끊어 화면 전체 쪽까지 안 올라왔다
	- 해결: 도형이 골라질 때 따로 알리고, 손가락으로 고른 것일 때만 서랍을 연다. 마우스 클릭으로는 안 연다
- 태블릿에서 확인하던 스크립트가 대답 없이 멈췄다
	- 원인: 여둘까 탭이 뒤로 가 있었다. 안드로이드 크롬은 뒤에 있는 탭을 얼려 둔다
	- 해결: 확인용 탭을 따로 열어 재고, 끝나면 그 탭만 닫는다. 쓰던 탭은 건드리지 않는다

### 두 손가락으로 확대하고 떼면 점이 하나 찍혔다

축척 보정을 시작하고 먼저 두 손가락으로 확대한 뒤 손을 떼면, 아무것도 안 찍었는데 상태줄이 「두 번째 점을 클릭하세요」로 넘어가 있었다.

두 손가락은 동시에 닿지도, 동시에 떨어지지도 않는다. 확대가 끝나 손을 떼는 순간을 캔버스가 「한 번 톡 누른 것」으로 읽어 점을 찍었다.

재기 모드에서는 한 손가락 터치를 전부 손가락 찍기 쪽이 먼저 받아 캔버스까지 보내지 않는다. 그러니 그 모드에서 캔버스가 받은 톡은 언제나 두 손가락 동작의 찌꺼기다.

```js
function onStagePick(e) {
  if (S.skipClick) { S.skipClick = false; return; }
  if (e.byTouch && isAimMode()) return;   // 확대하고 뗀 손가락이 점으로 찍히던 것
  // ...
}
```

- 해결: 재기 모드에서만 캔버스의 톡을 무시한다. 확대는 그대로 된다
- 같이 고친 것: 예전에 넣은 「터치로 한 번 찍으면 점도 하나」 검사가 바로 그 캔버스 길로 확인하던 거라 깨졌다. 지키려던 것은 같은 거름망을 쓰는 Shift+탭 자리로 옮겼고, 거름망을 빼면 검사가 깨지는 것까지 확인했다
