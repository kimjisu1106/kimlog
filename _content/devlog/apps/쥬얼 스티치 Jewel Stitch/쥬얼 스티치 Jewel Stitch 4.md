## 막힌 부분

- 패싯을 올리니 가장 밝은 면이 테이블보다 밝아졌다
  - 테이블을 바탕색으로 두기로 하면서 생긴 일이다. 가운데가 제일 밝지 않으면 눈이 멈출 데를 잃는다
  - 남은 한계: 폰에서 보고 거슬리지 않아 그대로 뒀다. 거슬리면 면 밝기를 1.00 아래로 눌러 테이블이 늘 제일 밝게 할 수 있다
- 벨트 보석이 갑자기 커졌다
  - 원인: 45도로 눌리면서 세 단이 차지하는 세로가 5.1r에서 3.1r이 됐는데, 띠 두께를 나누는 값만 고치고 띠 자체는 그대로 뒀다. 남는 자리가 전부 보석 크기로 갔다
  - 해결: 띠를 96에서 56으로 줄였다. 보석은 다시 14.5로 돌아왔고 벨트 영역이 270px에서 172px이 됐다
- 벨트가 세로로 뚱뚱해 24칸이 위쪽에 몰리던 문제가 따라서 풀렸다
  - 띠가 얇아지니 타원이 덜 둥글어져 둘레가 길어졌다. 따로 손대지 않았다

### 밝기를 1.08배로 올렸는데 화면에서는 안 올라갔다

면 밝기를 0.48에서 1.08배로 잡았는데, 가장 밝은 면이 바탕색과 똑같이 나왔다.

색을 어둡게 하는 함수를 그대로 쓴 게 원인이었다. 그 함수는 각 채널에 값을 곱하고 0~1로 자르는데, 1을 넘는 배수를 주면 자르는 데서 멈춘다. 1.08배든 2배든 결과가 같다.

```dart
// 1 이하는 곱하고, 1 위는 흰쪽으로 끌어올린다
Color _shade(Color c, double b) =>
    b <= 1 ? _mul(c, b) : _lighten(c, (b - 1) / 0.5);
```

- 해결: 1을 넘는 쪽은 흰색으로 섞는 함수를 따로 뒀다
- 어둡게와 밝게는 같은 축이 아니다. 곱셈은 0을 향하고 밝히기는 1을 향한다

### 보석 하나에 Path가 열 개가 됐다

판에 보석이 1,024개다. 전에는 색마다 Path 하나에 몰아 담아 색 수만큼만 그렸는데, 면이 여덟 개로 늘면서 칸마다 열 번을 그릴 판이 됐다.

면 번호마다 Path를 따로 뒀다. 같은 번호의 면은 밝기가 같으니 색 하나당 여덟 개면 되고, 그리는 횟수는 색 수 × 아홉이다. 칸 수와 무관하다.

그림자는 따로 먼저 깐다. 색마다 그림자와 보석을 번갈아 그리면 나중 색의 그림자가 먼저 그린 색 보석 위에 얹힌다.

- 해결: 면 번호별 Path 여덟 개 + 몸통 하나. 그림자는 전부 먼저
- 박힌 보석과 들뜬 보석이 같은 면을 쓰므로 Path를 공유한다. 둘을 가르는 것은 그림자와 테두리지 안쪽 음영이 아니다

### 같은 판을 찍으려고 구버전을 되돌려 빌드했다

비교 이미지를 만들려는데 바뀌기 전 화면이 폰에 없었다. 같은 자리를 눌러 찍었더니 판 상태가 서로 달라 비교가 안 됐다.

바꾸기 전 커밋에서 그리는 파일 둘만 꺼내 빌드하고, 레벨을 열어 한 번도 누르지 않은 상태로 찍었다. 섞는 데 쓰는 씨앗이 레벨 번호라 손대지 않으면 양쪽이 같은 판이다.

- 해결: `git checkout <커밋> -- <파일>`로 그 파일만 되돌려 빌드하고, 찍은 뒤 되돌린다
- 벨트가 줄면서 판이 아래로 내려와 같은 칸이 다른 자리에 있다. 판의 위아래 끝을 재서 자르는 자리를 맞췄다
