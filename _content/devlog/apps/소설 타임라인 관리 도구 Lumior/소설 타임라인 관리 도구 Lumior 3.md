## 오늘 한 일

- Claude에게 쓰기 불편한 이유를 먼저 조사시키고, 그 보고를 받아 세 단계로 나눠 진행했다. 단계마다 커밋을 따로 둬서 하나씩 되돌릴 수 있다
	- 이유: 노트 앱에는 소설 본문만 남기고 설정·해설은 이 도구로 옮겨 오기로 했다. 그러려면 도구가 느리고 읽기만 되는 상태로는 안 된다
- 1단계 — 켜는 속도와 첫 화면
	- 파일마다 수정 시각과 크기를 기억해 두고 바뀐 파일만 다시 읽는다. 그 기억을 디스크에 남겨서 다음 실행은 파일 목록만 훑는다
	- 처음 한 번은 21초, 그 뒤로는 다시 켜도 0.13초에 준비가 끝난다
	- 서버가 켜지자마자 뒤에서 미리 읽어 두고, 준비됐는지 묻는 주소를 따로 열었다
	- 실행 배치 파일이 같은 포트를 쥔 옛 서버를 먼저 끄고, 서버가 대답한 뒤에야 브라우저를 연다
	- 타임라인 첫 화면 — 한두 편짜리 해가 수십 줄 이어지던 구간은 이웃한 해끼리 묶고(56줄 → 23줄), 수백 편이 몰린 해는 달로 나눴다. 연대로 바로 건너뛰는 버튼을 달았다
	- 점검을 본문에만 건다. 설정·해설은 날짜가 없어도 정상이라 세던 것이 소음이었다(281 → 161). 끊긴 링크·내용 거의 없음·같은 제목 규칙을 더했다
- 2단계 — 탭 넷
	- 연표: 작품 속 연대 표기 여러 개를 한 축으로 편다. 연도를 넣으면 다른 표기로 바꿔 주고 그 해 인물 나이를 낸다. 환산 기준 중 확정되지 않은 것은 「가정」이라고 화면에 띄워 둔다
	- 상충: 설정끼리 어긋난 것을 문서 대신 도구가 목록으로 갖는다. 상태(열림·판단함·해소)와 판단을 앱 안에서 고친다
	- 장면: 연재 순서 플러그인의 목록과 실제 폴더를 맞대고, 아직 연재본에 안 들어간 장면을 연재본의 같은 이름과 본문 해시로 비교한다
	- 분량: 화마다 글자 수를 막대로 보여 준다. 평균 두 배가 넘는 화와 절반이 안 되는 화는 색으로 표시한다
- 3단계 — 앱 안에서 고치기
	- 문서 패널에 「여기서 고치기」. 본문이 아닌 문서에만 뜬다. 본문은 계속 노트 앱에서 쓴다
	- 덮기 전에 원본을 날짜별 백업 폴더에 남긴다. 작업 폴더가 git이 아니라 이게 유일한 되돌림이다
	- 연 뒤에 노트 앱에서 그 문서가 바뀌었으면 덮지 않고 알린다
	- 원본의 BOM과 줄바꿈 방식을 그대로 두고, 쓴 뒤 바이트로 다시 읽어 확인한다
	- 설정 폴더에 새 문서를 만들 수 있게 했다. 같은 이름이 어디에든 있으면 거부한다(문서 링크가 이름으로 걸려서 둘이면 갈린다)
	- 지우는 기능은 만들지 않았다
	- 인물 탭: 카드·연표·관계 상대·상충·관련 설정 문서·등장 장면을 한 장에 모았다
	- 탭이 열한 개가 돼서 보기 / 관리 두 묶음으로 나눴다
- 저장·생성 시험은 작업 폴더를 통째로 복사한 사본에 대고 했다. 환경변수 하나로 서버가 사본을 보게 했다

## 막힌 부분

- 실행 배치 파일이 3초를 기다렸다가 브라우저를 열었는데, 서버가 늦게 뜨면 「연결할 수 없음」 화면이 먼저 떴다
	- 해결: 시간을 기다리지 않고 서버의 준비 주소가 대답할 때까지 0.5초 간격으로 묻는다
- 인물 연표에서 퇴장을 뜻하는 낱말이 든 사건을 끝으로 치게 했더니, 그 말을 부정하는 사건과 다른 사람이 겪은 사건까지 걸렸다
	- 해결: 문장이 그 말로 시작하거나 끝나거나 괄호로 그 말만 단 경우만 친다
	- 남은 한계: 사건 이름을 사람이 적으니 언젠가 또 샌다. 사건에 「끝」 여부를 따로 적는 칸이 맞다

### 창을 다시 볼 때마다 한 탭에서만 조용히 오류가 났다

노트 앱에 다녀오면 창 포커스를 받아 데이터를 다시 불러온다. 그 함수가 관계 탭일 때 그 탭의 상태 변수를 비우는데, 그 변수는 화면을 그리는 함수 안쪽에 선언돼 있었다.

```js
function initTimeline(){
  let relData=null;          // 안쪽 스코프
}
async function refreshData(){
  relData=null;              // 바깥에서는 안 보인다 → ReferenceError
}
```

화면은 그대로라 겉으로는 「관계 탭만 가끔 안 바뀐다」로만 보였다. 탭 전환을 표 하나로 묶으면서 상태 변수를 모아 보다가 드러났다.

- 해결: 상태 변수를 바깥 스코프로 옮겼다

### 문서를 바꾸는 사이 앞 문서의 버튼이 남아 있었다

「여기서 고치기」는 문서를 불러온 뒤에 보일지 말지 정한다. 불러오는 동안에는 앞 문서의 상태가 그대로라, 고칠 수 있는 문서를 보다가 본문을 누르면 잠깐 동안 본문에도 그 버튼이 떠 있었다.

- 해결: 문서를 누르는 순간 먼저 숨기고, 불러온 뒤에 다시 정한다
- 덤: 불러오는 사이 다른 문서를 눌렀으면 늦게 온 응답은 버린다

### 다시 그리면 쓰던 글이 날아간다

포커스 때 다시 불러오는 동작이 지금 탭을 통째로 다시 그린다. 상충 탭에서 판단을 쓰다가 노트 앱에서 근거 문서를 확인하고 돌아오면, 쓰던 내용이 사라질 자리였다.

- 해결: 상충 탭은 노트 파일을 보지 않으니 포커스 때 다시 그리지 않는다. 문서 편집은 별도 패널이라 다시 그리기와 무관하고, 저장 안 한 채 닫거나 창을 떠나면 묻는다
