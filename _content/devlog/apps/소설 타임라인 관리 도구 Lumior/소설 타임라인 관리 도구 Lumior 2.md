## 오늘 한 일

- 에피소드 탭 — 묶음을 손으로 적어 둔 문서 대신, 각 문서 frontmatter의 칸에서 거꾸로 모아 만든다
	- 이유: 손으로 적은 묶음은 본문을 고쳐도 따라오지 않아 낡는다. frontmatter는 장면과 같이 움직인다
	- 그룹을 편수·기간 카드로 보여 주고, 누르면 그 묶음의 문서가 날짜순으로 펼쳐진다
- 설정 탭 — 날짜가 없는 게 맞는 문서를 따로 모아 본다
	- 축 둘. 폴더는 저장된 자리로, 키워드는 제목에 같은 말이 3편 이상 든 것끼리
	- 키워드 축이 폴더를 가로지른다 — 여러 폴더에 흩어진 같은 주제가 한자리에 모인다
	- 검색과 정렬(많은 순 / 가나다) 추가
	- 타임라인에서는 이 문서들을 기본으로 숨긴다. 왼쪽 토글로 되돌릴 수 있다
- 문서 보기를 공용 패널로
	- 어느 탭에서든 제목을 누르면 오른쪽 패널에서 바로 읽힌다. 외부 편집기는 고칠 때만
	- 외부 라이브러리 없이 최소 마크다운 — 헤딩·중첩 목록·코드블록·인용·구분선
	- 문서끼리 거는 링크는 눌러서 이동하고, 대상이 없으면 흐리게 표시한다
- 드래그로 폴더 옮기기 — 읽기 전용이던 절대 규칙에 예외를 하나 열었다
	- 내용은 한 바이트도 안 건드리고 자리만 바꾼다
	- 서버가 막는 것: 작업 폴더 밖·확장자 다름·원본 없음·대상 폴더 없음·같은 폴더·덮어쓰기, 그리고 연재 순서 플러그인이 쥐고 있는 파일
	- 놓기 전에 「어디서 어디로」를 보여 주고 확인받는다
- 실행 배치 파일을 ASCII·CRLF로 다시 썼다

## 막힌 부분

- 실행할 때마다 「…은(는) 내부 또는 외부 명령이 아닙니다」가 한 줄 뜨고 나서야 돌았다
	- 원인 둘: 주석이 UTF-8 한글인데 cmd는 CP949로 읽어 깨진 글자가 명령으로 해석됐고, 줄바꿈이 LF뿐이었다
	- 해결: 주석을 ASCII로 바꾸고 CRLF로 다시 썼다. `.gitattributes`에 `*.bat text eol=crlf`로 못 박아 다시 LF로 돌아가지 않게 했다
	- 덤: 실패했을 때 창이 바로 닫히지 않게 `pause`를 걸었다. 그동안은 뭐가 잘못됐는지 볼 수가 없었다
- 서버를 고쳤는데 계속 옛 동작이었다
	- 옛 프로세스가 포트를 잡고 있어 새 서버가 바인드에 실패했는데, 로그를 안 보면 모른다. 띄우는 명령은 성공한 것처럼 끝난다
	- 해결: 포트를 쥔 프로세스를 먼저 끝내고 띄운다. 로그에서 바인드 실패를 확인하는 절차를 넣었다

### 새 레이아웃이 900px에 갇혔다

3단으로 만든 화면이 1882px 창에서 900px만 쓰고 오른쪽이 비어 있었다. 본문이 한 줄에 스무 자밖에 안 들어갔다.

원인은 오래된 전역 규칙이었다.

```css
main{flex:1;padding:18px 26px;max-width:900px}
```

새로 만든 칸도 `<main>`이라 이 규칙에 걸렸다. 기존 화면에는 맞는 값이라 아무도 의심하지 않는다.

- 해결: 새 칸만 `max-width:none`으로 풀었다
- 같이 드러난 것: 그 전에 만든 탭도 똑같이 갇혀 있었는데 못 보고 있었다. 전역 규칙을 건드리는 대신 새 요소에서 푸는 쪽을 골랐다

### 404가 조용히 성공으로 넘어갔다 — 같은 자리를 두 번 틀렸다

문서를 못 불러오는데 오류도 안 뜨고 아무 일도 안 일어났다. 콘솔을 보니 `Cannot read properties of undefined`였다.

```js
try{ d = await fetch(url).then(r => r.json()); }
catch{ d = {error:'불러오지 못했습니다'}; }
if(d.error){ /* … */ }
```

`fetch`는 404에서 예외를 던지지 않는다. 응답 본문도 JSON이라 `.json()`이 성공하고, 그 결과에는 기대한 칸이 없다. `catch`에도 안 걸리고 `error`도 없으니 실패가 성공처럼 흘러간다.

파일 옮기기에서 같은 일이 또 났다. 드래그로 놓으면 아무 일도 안 일어나는데 오류도 없었다. 서버가 옛 버전이라 그 주소가 404였던 것이다.

- 해결: 응답 상태와 기대하는 칸이 실제로 왔는지를 직접 본다. 404면 「서버가 옛 버전일 수 있다」까지 알린다
- 남은 교훈: `try/catch`만 두르면 안전해 보이는데, 네트워크 호출에서 그건 절반만 막는다

### HTML에서 뺀 요소를 코드가 계속 찾고 있었다

문서 보기를 공용 패널로 옮기면서 쓰던 칸을 HTML에서 지웠는데, 그 칸을 쓰던 코드가 두 줄 남아 있었다. 묶음을 고를 때마다 거기서 터졌고, 그 뒤에 붙는 드래그 핸들러가 아예 등록되지 않았다.

겉으로는 「드래그가 안 된다」로만 보인다. 드래그 코드에는 문제가 없었다.

- 해결: 남은 참조 둘을 걷어냈다
- 남은 한계: 기능을 옮길 때 옛 요소를 지우는 것까지는 하는데, 그걸 쓰던 코드를 전부 따라가는 건 눈으로 해야 한다

### 검증 코드가 옛 자리로 새 문자열을 잘랐다

frontmatter만 고치고 본문은 그대로인지 대조하는 코드에서, 고치기 전 문자열의 위치로 고친 뒤 문자열을 잘라 비교했다. frontmatter가 짧아지면 그 자리가 밀린다.

```python
out = head + new_fm + rest
assert out[m.end(2):] == rest   # m은 옛 문자열의 매치다
```

- 해결: 쓴 뒤 다시 읽어서 새로 매치한 자리로 대조한다
- 다행인 것: 검증이 먼저 터져서 한 파일도 잘못 쓰이지 않았다. 같은 실수를 전에도 했는데 그때도 검증이 잡았다
